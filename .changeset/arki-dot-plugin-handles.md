Breaking: `plugin()` publishes through `provides` factories, exactly like `feature()` (`provides: { db: () => openDb() }`). Each factory gets the plugin's needs plus `$app`/`$plugin`/`$config` and may be async; the kernel awaits them in key order. `boot` is side effects only: a value-returning plugin `boot` no longer compiles, and `InferredProvides` is removed. Every plugin now carries typed handles before boot: `database.provides.db` is a `Handle<T, 'db'>` (a `Token` plus `provider` and `.lazy`), so consumers write `needs: { db: database.provides.db }` and name the type once with `Provided<typeof database.provides.db>`. `Handle`, `LazyHandle`, `Handles`, `Provided` and `ProvidesFactories` now live in the plugin contract (re-exported from `@arki/dot`, `@arki/dot/plugin` and `@arki/dot/feature`). `Plugin.provides` is required (wire-keyed handles) and `Plugin.factories` holds the factories. `rename()` rebuilds the handles on the new keys and name; a handle taken before the rename keeps the old key and fails the builder guard. The kernel checks every plugin's needs against every plugin's static provides at `configure()`: `DOT_LIFECYCLE_E020` names a provider mounted after its consumer, with a role-aware fix ("Move X before Y in .features([...])" or "Mount X with .use() before Y"), and a ring through adapters is `DOT_LIFECYCLE_E019`; `E012` remains only for needs no plugin declares. `dot explain` prints one labelled edge per capability for adapters too, without booting. A feature's slice record is one of its plugin's provides entries. `providesOf()` accepts plugins as well as features. `handle.lazy` needs receive a `Lazy<T>` in `resolveNeeds()` as in hook contexts. New `fake(handle, value)` in `@arki/dot/test-harness` mounts a fake under a real handle, type-checked against it.
