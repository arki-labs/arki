M4: failure matrix, benchmarks and docs, with three behaviour changes. **Resume or reset now depends on a cursor's age alone** (`replayMs`): the replay ring evicts by age only, so writes to tables a client cannot see no longer turn its resume into a reset. `limits.replayFrames` (default 65 536, was 4096) is now a hard overload cap: reaching it starts a new epoch, ends every stream with `gap` and resets every client together, logged at warn. Cursors seal the position's time and grow from 64 to 75 characters (still opaque; still accepted by `parseLiveCursor`). **A `change` frame is sealed once** and its cursor shared by every stream (one AES-GCM call per frame instead of per client). **The client drops a silent connection**: no byte for 35 s (two missed heartbeats) or a browser `offline` event ends the stream and reconnects with the cursor, so a half-open connection no longer stays `live`. Also: the Postgres failure suite (16 and 18) and session tests, a Playwright run on a TanStack Start fixture, `test:peers` and `test:pack` checks, `bench/live.bench.ts` (numbers pending an idle run), a compiled Dot example, and README sections on write paths, security, operations, account switches and when to pick Electric, Zero or PowerSync instead.
