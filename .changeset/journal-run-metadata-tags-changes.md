A workflow step changes its run's metadata and tags while it runs: `ctx.metadata.set(patch)`, `increment(key, by?)`, `append(key, value)`, `remove(key)` and `ctx.tags.add(...tags)`, in a step or an undo. Each call commits at once as one event on the run (`MetadataChanged` with the `change`, or `RunTagged` with the new tags), so a reader sees the progress while the step still runs, and a replay rebuilds the row. A refusal (`CommandConflict` once the run has finished, `CommandInvalid` for a wrong value type, metadata over 256 KiB or more than 10 tags) is the value the call returns and does not fail the step. Operators make the same changes with `journal.workflows.setMetadata(db, { runId, change }, op)` and `addTags(db, { runId, tags }, op)`; the event records `op`. A call never rejects, so a progress report may be left un-awaited: it runs through the new `EffectContext.runUnwatched` (the attempt's fenced runner without the refusal watch), so a stale attempt writes nothing and a late refusal never fails the step. `workflow_runs` gets the column `field_changes integer not null default 0` (push the schema): it counts the metadata and tag events, and the Foreman workflow actions take their revision as `version - field_changes`, so progress reports no longer void an approval. New types: `MetadataChange`, `MetadataContext`, `TagsContext`, `MetadataOutcome`, `TagsOutcome`, `RunMetadata`.
