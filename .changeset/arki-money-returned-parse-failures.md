---
'@arki/money': minor
---

Parsers return, builders throw. `Money.parse`, `Money.fromJSON`, `parseMoney`, `createMoneyParser(...).parse`, `fromProviderUnits` and `fromStripeAmount` return the value or an `@arki/failure` value instead of throwing on bad outside input. New doors `Currency.parse(code, currencies?)` and `Currency.parseNumeric(numeric)` read currency codes from outside. Failures, listed once in `MONEY_FAILURES` and carrying no input text: `InvalidMoneyText` (`money.invalid_text`, 400), `InvalidMoneyShape` (`money.invalid_shape`, 400), `UnknownCurrency` (`money.unknown_currency`, 400), `RoundingNecessary` (`money.rounding_necessary`, 400), `AmountOutOfRange` (`money.out_of_range`, 400), `InputTooLarge` (`money.input_too_large`, 413), `UnsupportedLocale` (`money.unsupported_locale`, 400) and `ProviderAmount` (`money.provider_amount`, 422). `createMoneyParser` and `parseMoney` return `UnsupportedLocale` for a locale tag `Intl` rejects.

Breaking: `MoneyParser#tryParse` is removed; `parse` now returns failures. Builders (`money`, `Money.of`, `Money.fromMinor`, `Currency.of`, `Currency.fromNumeric`, `stripeRule`, `toProviderUnits`, `toStripeAmount`) and arithmetic still throw. A provider rule with a step below 1 or a bad scale now throws `InvalidArgumentError` (a zero step used to throw a bare `RangeError`). A `bigint` product past about 10 000 digits throws `ResourceLimitError` before it is built, instead of crashing Hermes. Drizzle columns still throw on bad stored values, so a query rejects instead of returning a wrong amount. `@arki/failure` is now a runtime dependency. See `docs/upgrades/0.1.0-to-0.2.0.md`.
