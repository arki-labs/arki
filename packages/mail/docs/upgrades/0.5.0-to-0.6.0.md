# Upgrade @arki/mail 0.5.0 to 0.6.0

You must act if you call `send`, `sendRaw` or `mailOutbox().enqueue` with an `idempotencyKey`, or build a transport, mailer or outbox from settings that can now be refused; everyone else can skip it.

## What changed

- `mailOutbox().enqueue` no longer fails the caller's write with a raw Postgres error on user data. It returns `MailInvalidMessage` and queues nothing when:
  
  - any field of the rendered mail holds a NUL character (U+0000), which the jsonb row refuses (SQLSTATE 22P05);
  - the `idempotencyKey` is empty, holds a NUL character (22021), or is over 256 characters (22001, the journal's `dedupe_key varchar(256)`), counted in code points.
  
  Breaking: `send`, `sendRaw` and `compose` also return `MailInvalidMessage` for a NUL character in any field, so `send` and `enqueue` agree. No mail can carry it.
- Settings no request can use now fail when the transport, mailer or outbox is built, as `MailError` `ARKI_MAIL_E001`, instead of every send reading as `mail.uncertain` ("the mail may have been sent") or a raw error:
  
  - an `apiKey` (Resend, Unosend), `apiToken` (Cloudflare) or SES `credentials.accessKeyId` / `sessionToken` holding a line break, a NUL character or a character above U+00FF (`fetch` refuses such a header before sending). The message never echoes the key.
  - a Mailpit `baseUrl` that is not an http(s) URL without credentials; an empty Cloudflare `accountId` or one with a lone surrogate (was a raw `URIError`); an SES `region` that is not a host name label.
  - a `quotaPerMonth` that is not a whole number of at least 0 (NaN silently ignored the budget), and an outbox `maxBytes` that is not a whole number above 0.
  
  Breaking: `send` and `sendRaw` return `MailInvalidMessage` for an `idempotencyKey` holding a line break, a NUL character or a character above U+00FF, on every transport (Resend sends it as a header, and `failover` may pick Resend). Use a Latin-1 key, such as a hash.
- A lone surrogate (such as `'\ud800'` alone) in any field of a message is `MailInvalidMessage`, like a NUL character: it is not text, and the outbox's jsonb column refused it with a raw Postgres 22P02. `enqueue` also returns `MailInvalidMessage` for an `idempotencyKey` holding a lone surrogate (the driver stored it as U+FFFD, so two keys shared one dedupe slot) and for an `expiresAt` that is an Invalid Date (was a raw `RangeError`).
  
  Breaking: `send` and `sendRaw` now return `MailInvalidMessage` for a message with a lone surrogate instead of sending it.
- `KVLike.get` now takes any Standard Schema of number (`StandardSchemaV1<unknown, number>`) instead of a Zod type; an `@arki/kv` client still fits. `QueuedArgs` in `@arki/mail/pg` is a plain TS type and the queue row schemas are internal, so `.`, `./pg` and `./outbox` name no Zod types.
- `mailOutbox.enqueue` no longer throws a plain `Error` when the job holding an idempotency key is sent and deleted between the refused insert and the lookup. The key is free then, so it inserts again and returns `{ jobId, deduped: false }`. If other writers keep taking the key for three tries in a row, it returns the new `MailEnqueueContended` (`mail.enqueue_contended`, 503, `data.attempts`) and queues nothing; retry the write. `MailTooLarge`, `MailInvalidMessage` and `MailEnqueueContended` are now exported from `@arki/mail`, so callers can branch on them with `.is()`.

## Steps

1. Use a Latin-1 idempotency key. A key with a line break, a NUL character or a character above U+00FF now returns `MailInvalidMessage`. A hash is a safe key.

   Before:

   ```ts
   await mailer.send(template, input, { to, idempotencyKey: `welcome-${user.name}` });
   ```

   After:

   ```ts
   await mailer.send(template, input, { to, idempotencyKey: `welcome-${user.id}` });
   ```

2. Handle `MailInvalidMessage` from `send`, `sendRaw`, `compose` and `enqueue`. It now covers a NUL character or a lone surrogate in any field.

   Before:

   ```ts
   const queued = await outbox.enqueue(tx, template, input, { to, idempotencyKey: key });
   ```

   After:

   ```ts
   const queued = await outbox.enqueue(tx, template, input, { to, idempotencyKey: key });
   if (MailInvalidMessage.is(queued)) return queued;
   ```

3. Handle `MailEnqueueContended` from `enqueue`. Other writers kept taking the key, so nothing was queued. Retry the write.

   After:

   ```ts
   if (MailEnqueueContended.is(queued)) return queued;
   ```

   Import `MailInvalidMessage`, `MailTooLarge` and `MailEnqueueContended` from `@arki/mail`.

4. Check your settings. Building the transport, mailer or outbox now throws `MailError` `ARKI_MAIL_E001` for an API key with a line break, a bad Mailpit `baseUrl`, a `quotaPerMonth` that is not a whole number of at least 0, or an outbox `maxBytes` that is not a whole number above 0. Fix the value and the error goes away.

5. If you wrote your own `KVLike`, make `get` accept `StandardSchemaV1<unknown, number>`. An `@arki/kv` client already fits.

## Verify

Run your mail tests and the type check. A clean run proves the new failures are handled.

```sh
bun run test && bun run typecheck
```
