# Upgrade @arki/dot 0.9.0 to 0.10.0

Act on this only if you serve requests through `@arki/tanstack-start` and read its error bodies, or you build a gateway from `requestServices` with no converted features yet. Everyone else can upgrade without changes: the `toJsonObject` check accepts and refuses the same values as before.

## What changed

- `@arki/tanstack-start`: the cron 401, request crashes, identity-lookup throws and the boot 503 now answer with a typed failure in the `{ error: { code, message } }` envelope (`tanstack_start.unauthenticated`, `tanstack_start.internal`, `tanstack_start.unavailable`). A failure thrown by `rpc`, `session` or `createContext` answers with its own status. The cron 401 no longer says which check failed.
  
  `@arki/dot`: `toJsonObject` checks the value with a schema instead of hand-written guards. Same inputs are accepted and refused, same `ARKI_DOT_E032` error.
  
  `@arki/tanstack-start`: `registerPwa` catches a failed load of `virtual:pwa-register` (offline first visit, blocked chunk, build without the PWA plugin) and logs a warning at `arki:tanstack-start`. No unhandled rejection; the app runs without offline support.

## Public API changes

Removed:

- Nothing.

Changed:

- `requestServices([])` now returns `{ provides: Readonly<Record<never, never>> }`. Before, `provides` was typed `unknown`, so `providesOf` refused the unit.
- `toJsonObject` checks the value with a Zod schema (`z.record(z.string(), z.json())`) instead of hand-written guards. The same values pass and fail. It still throws `DotManifestError` with code `ARKI_DOT_E032`.
- `dot new` scaffolds apps against `@arki/db` 0.5.0, `@arki/journal` 0.4.0 and `@arki/ui` 0.2.0. Before: 0.4.0, 0.3.0 and 0.1.6. The scaffolded `app.ts` types the database as `NodePgDatabase<typeof relations> | PgliteDatabase<typeof relations>` instead of `MigratableDb<typeof relations>`.

Added:

- `DotManifestError.cause`: the schema failure that explains which part of the value was refused.

Wire change in `@arki/tanstack-start` (same release wave): the cron 401, request crashes, identity-lookup throws and the boot 503 answer in the `{ error: { code, message } }` envelope with the codes `tanstack_start.unauthenticated`, `tanstack_start.internal` and `tanstack_start.unavailable`. A failure thrown by `rpc`, `session` or `createContext` answers with its own status. The cron 401 no longer says which check failed.

## Steps

1. If a client or a monitor reads the error body of a `@arki/tanstack-start` app, read the `error.code` field instead of the old text. Match on the code, never on the message.

   ```ts skip="before: the 0.9.0 API"
   // A crash answered with a bare text body. The cron 401 named the failed check.
   const text = await response.text();
   const signedOut = text.includes('Unauthorized');
   ```

   ```ts
   type ErrorBody = { readonly error: { readonly code: string; readonly message: string } };

   export async function isSignedOut(response: Response): Promise<boolean> {
     const body: ErrorBody = await response.json();
     return body.error.code === 'tanstack_start.unauthenticated';
   }
   ```

2. If your app mounts only legacy routers and a gateway beside them, pass an empty list to `requestServices`. Remove the cast you used to make `providesOf` accept it.

   ```ts skip="before: the 0.9.0 API"
   const gateway = requestServices([]);
   // `gateway.provides` was `unknown`, so this needed a cast:
   const handles = providesOf([gateway as { readonly provides: Record<never, never> }]);
   ```

   ```ts
   import { providesOf, requestServices } from '@arki/dot/feature';

   const gateway = requestServices([]);
   const handles = providesOf([gateway]);
   ```

3. If you call `toJsonObject` and read the refusal, you can now read why from `cause`. The code is the same.

   ```ts
   import { DOT_MANIFEST_ERROR_CODE, DotManifestError, toJsonObject } from '@arki/dot';

   export function whyRefused(value: unknown): unknown {
     try {
       toJsonObject(value);
     } catch (error) {
       if (error instanceof DotManifestError && error.code === DOT_MANIFEST_ERROR_CODE) {
         // `error.cause` is the schema failure: it names the part that is not plain JSON.
         return error.cause;
       }
       throw error;
     }
     return undefined;
   }
   ```

4. If you made your app with `dot new` on an older version and you move to `@arki/journal` 0.4.0, change the database type in `src/app.ts` to the two Postgres drivers.

   ```ts skip="before: the 0.9.0 API"
   import type { MigratableDb } from '@arki/db/migrate';

   type AppDb = MigratableDb<typeof relations>;
   ```

   ```ts skip="needs the relations of your own app"
   import type { NodePgDatabase } from 'drizzle-orm/node-postgres';
   import type { PgliteDatabase } from 'drizzle-orm/pglite';

   type AppDb = NodePgDatabase<typeof relations> | PgliteDatabase<typeof relations>;
   ```

## Verify

```sh
bun run typecheck
```

Run it in your app. It must pass with no errors. A gateway with no features that failed before now compiles.
