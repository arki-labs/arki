# Upgrade @arki/dot 0.8.0 to 0.9.0

Act on this only if something else on your machine uses port 4321 while `dot dev` runs, or a script parses the `dot dev` startup output. Everyone else can upgrade without changes: the new parts are opt-in.

## What changed

- `dot dev` serves a console on `--console-port` (default 4321) with one page per projection that registers `console: { title }`. The projection module exports `consolePage(document)`; the console runs `dot explain --as <format> --page` for each request and wraps the HTML in a shell with light and dark tokens. `dot explain --page` is new. `ProjectionManifest` gains `console`. A taken console port prints a warning and `dot dev` runs without the console. No demo impact: the console has no demo.

## Public API changes

Added:

- `dot dev --console-port <port>` (default `4321`, handed to the runner as `CONSOLE_PORT`) and `dot dev --no-console`.
- `dot explain --page`: also renders a projection's console page.
- `ProjectionManifest.console?: { title: string }`. Optional, so existing manifests still type-check.
- A projection module may export `consolePage(document)`, which returns the page's HTML.

Nothing was removed or renamed.

## Steps

1. If port 4321 is taken on your machine, pick another console port or turn the console off. A taken port only prints a warning; `dot dev` still runs without the console.

   ```sh
   # before
   dot dev
   # after: another port, or no console
   dot dev --console-port 4400
   dot dev --no-console
   ```

2. Optional: give a projection a console page. Add `console: { title }` to its manifest and export `consolePage(document)` from the projection module. [Adapter authoring](../adapter-authoring.md) shows a full example, and [the CLI reference](../cli.md) lists the flags.

## Verify

```sh
dot dev --no-console
```

Your app must start exactly as it did on 0.8.0. Then run `dot dev` without the flag and open `http://localhost:4321` to see the console.
