# Upgrade @arki/dot 0.10.0 to 0.11.0

You must act if you pass `renderTimeline` a `barWidth` that is not a whole number from 1 to 1000, pass `SIGKILL` or `SIGSTOP` to `hookSignals`, or call `runNew` or `runDev` and expect a thrown error; everyone else can skip it.

## What changed

- `dot new` and `dot dev` now return their file-system problems instead of throwing them.
  
  - `runNew` returns `dot.template_missing` when the template folder is missing or a template file cannot be read. Before, only an empty folder returned it; a missing folder threw a raw `ENOENT`.
  - `runDev` returns the new `dot.dev_state_failed` (data `{ statePath, reason }`) when it cannot create `.local/dot/dev.json`, for example in a read-only or full project folder. `releaseDevState` no longer rejects: a state file it cannot remove is logged at warn, so the session keeps its own result.
  - Breaking: `renderTimeline` checks `barWidth` up front. It must be a whole number from 1 to 1000; any other value fails an `invariant` with a clear message instead of a `RangeError` from deep in the renderer.
  - Breaking: `hookSignals`'s `signals` option takes only termination signals a process can catch (`SIGTERM`, `SIGINT`, `SIGHUP`, `SIGQUIT`, `SIGBREAK`, `SIGUSR2`). `SIGKILL` and `SIGSTOP` are now a type error instead of a runtime crash that left some handlers hooked.
  - `dot new` templates pin `@arki/db` 0.5.1 and `@arki/journal` 0.4.1, the published versions.
  - Failure data schemas in `@arki/dot/cli` are zod schemas now, and each exported `...Data` type is the schema's output. `DoctorFailed` checks the whole diagnostics snapshot, not only that its fields are arrays.

## Steps

1. Upgrade `@arki/dot` to 0.11.0.

2. Keep `barWidth` a whole number from 1 to 1000. Any other value now fails an `invariant`.

   Before:

   ```ts skip="fragment: upgrade before and after snippet"
   renderTimeline(report, { barWidth: 0 });
   ```

   After:

   ```ts skip="fragment: upgrade before and after snippet"
   renderTimeline(report, { barWidth: 50 });
   ```

3. Remove `SIGKILL` and `SIGSTOP` from the `signals` option of `hookSignals`. A process cannot catch them, and they are now a type error.

   Before:

   ```ts skip="fragment: upgrade before and after snippet"
   hookSignals(app, { signals: ['SIGTERM', 'SIGKILL'] });
   ```

   After:

   ```ts skip="fragment: upgrade before and after snippet"
   hookSignals(app, { signals: ['SIGTERM', 'SIGINT'] });
   ```

4. Check the result of `runNew` and `runDev` with `isFailure` instead of a `try` block. `runNew` returns `dot.template_missing` for a missing template folder. `runDev` returns `dot.dev_state_failed` when it cannot write `.local/dot/dev.json`.

   Before:

   ```ts skip="fragment: upgrade before and after snippet"
   try {
     await runNew(options);
   } catch (error) {
     report(error);
   }
   ```

   After:

   ```ts skip="fragment: upgrade before and after snippet"
   const result = await runNew(options);
   if (isFailure(result)) report(result);
   ```

   In a script where a failure is a bug, use `orThrow(await runNew(options))`.


## Verify

Run `bun pm ls | grep @arki/dot`. The output names `@arki/dot@0.11.0`. Then run your type check: it reports no error for `hookSignals`.
