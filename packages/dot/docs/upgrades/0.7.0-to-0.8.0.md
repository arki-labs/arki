# Upgrade @arki/dot 0.7.0 to 0.8.0

> This note uses the names of that version. Today `plugin()` is `infra()` or `entrypoint()`, `driver()` and `driven()` are `entrypoint.fromFeatures()` and `infra.fromFeatures()`, and `@arki/dot/plugin` is `@arki/dot/unit`. Write the new names in new code.

Apps and packages that import `Lazy` or `resolveLazy` from `@arki/ts`, or the Dot adapter from `@arki/env/dot`, must change those imports; everyone else can skip this guide and take the new `dot env` command, `@arki/dot/vite` and `createAppRuntime` `eager` option as they come.

## What changed

- `Lazy<T>` and `resolveLazy` move from `@arki/ts` to `@arki/dot/plugin` as `Deferred<T>` and `resolveDeferred`. They are the "value now, or a thunk the adapter calls at boot" shape that Dot adapters accept, and the old name clashed with Dot's own `Lazy<Value, Cleanup>` service handle. Behaviour is unchanged. `@arki/ts` no longer exports them; to upgrade, import `Deferred` and `resolveDeferred` from `@arki/dot/plugin`.

  `@arki/http` (`port`) and `@arki/kv` (`kv()`, `kv.optional()`) now type their deferred options as `Deferred<T>`, the same shape as before, and no longer depend on `@arki/ts`. `@arki/env` drops an `@arki/ts` dependency it never imported.

  demo impact: none (neither demo imports `Lazy` or `resolveLazy`).

- `dot env`: encrypted env files from the command line. `init` (header, private key, `.gitignore`, agent read-deny), `set` (encrypts with the public key only, so agents can write without reading; refuses a no-op), `get` (shape only; `--reveal` on a terminal), `ls`, `check` (CI gate: unloadable files, refused keys, plaintext `secret()` keys in tracked files, tracked `.env.keys`), `encrypt` (`--from` imports a plaintext file), `decrypt`, `rotate` (every `.env.<env>` file together), `run -- <cmd>` (passthrough; redacts secrets when stdout is not a terminal), `explain`, and `keys push|pull` (1Password, key via stdin). Failures `dot.env_*`. Commands read `secret()` keys from the app's `src/env.ts` with validation skipped; where it cannot be imported (Node) they report `dot.env.schema_unavailable`, which fails `check` when a tracked file holds a plain value. `dot dev` now opens encrypted values in env files before its database check.

  `@arki/cli`: a positional array argument is no longer split on commas (`node -e "f(a, b)"` stayed two pieces).

- `@arki/dot/vite`: a Vite plugin that configures the app while Vite builds. An app that does not configure fails `vite build` instead of the first production request; the manifest and every registered projection document (for example `openapi.json`) are written into the server output. `vite dev` re-checks on every change to the app's module graph. `createAppRuntime` gains `eager`: start the app when the module loads instead of on the first `get()`, for production servers that should boot before they serve.

- The Dot adapter moved from `@arki/env/dot` to `@arki/dot/env`. `@arki/env` drops its `@arki/dot` peer; `@arki/dot` depends on `@arki/env`. `@arki/env/core` exports `formatIssues`. Migration: `packages/env/docs/upgrades/0.1.0-to-0.2.0.md`.

## Public API changes

- Moved: `Lazy<T>` and `resolveLazy` leave `@arki/ts`. They are now `Deferred<T>` and `resolveDeferred` in `@arki/dot/plugin`.
- Moved: the Dot adapter `env()` leaves `@arki/env/dot` and is now in `@arki/dot/env`. `ENV_PLUGIN_ERROR_CODES`, `EnvDotOptions` and `EnvServices` move with it.
- Added: `@arki/dot/vite` exports `dotVite`, `describeDotApp` and the types `DotViteOptions`, `DotBuildDescription` and `DescribeDotAppOptions`.
- Added: the `eager` option of `createAppRuntime` (`@arki/dot/runtime`). It defaults to `false`.
- Added: the `dot env` command group (see "What changed").
- Added: `formatIssues` in `@arki/env/core`.
- Removed: the builder methods `.use()`, `.useAll()` and `.serve()`. Use `.infra(...)` and `.entrypoints(...)`.
- Removed: `errorCaptureMiddleware` and `ErrorCaptureInfo` from `@arki/dot/orpc`. Use the `reportErrors` observer.
- Added: handler lifecycle events (`kind: 'handler'`, `DotHandlerLifecycleEvent`), the `$handlers` kernel context key (`DotHandlerObserver`, `DotHandlerRef`), `handlerObserverOf` in `@arki/dot/feature`, and the observers `reportErrors` and `logHandlers` in `@arki/dot`. `bind(logic)` emits an rpc event pair per call.

## Steps

1. Replace `Lazy` and `resolveLazy` imports from `@arki/ts`. Skip this step if you never used them.

   ```ts skip="before and after fragment of a migration"
   import type { Deferred } from '@arki/dot/plugin';
   import type { Lazy } from '@arki/ts';
   import { resolveDeferred } from '@arki/dot/plugin';
   import { resolveLazy } from '@arki/ts';

   // before

   // after
   ```

   Rename the type use `Lazy<T>` to `Deferred<T>` and each call `resolveLazy(x)` to `resolveDeferred(x)`. The behaviour is the same. Add `@arki/dot` as a dependency of the package if it is missing.

2. Change the Dot env adapter import. Skip this step if you do not use `@arki/env/dot`.

   ```ts skip="before and after fragment of a migration"
   // before

   // after
   import { env } from '@arki/dot/env';
   import { env } from '@arki/env/dot';
   ```

   The `env()` call and its options stay the same. For encrypted env files, see `packages/env/docs/upgrades/0.1.0-to-0.2.0.md`.

3. `.use()`, `.useAll()` and `.serve()` are removed. The builder is `defineApp(name).infra(...).features([...]).entrypoints(...)`. Replace each call, and merge a run of calls into one list. A list is checked in order, like separate calls.

   ```ts skip="before: the old builder steps"
   // before
   defineApp('shop').use(database).use(cache).useAll(extras).serve(http);

   // after
   defineApp('shop').infra(database, cache, ...extras).entrypoints(http);
   ```

   A unit that holds domain logic belongs in `.features([...])`, not `.infra(...)`. A unit that calls into the app and runs between start and stop (an HTTP server, a worker) is an `entrypoint(...)` mounted with `.entrypoints(...)`. The order is infra, then features, then entrypoints.

Nothing else is required. To opt in to the additive features, add `dotVite({ ... })` to the app's `vite.config.ts` (see `DotViteOptions`), and pass `{ eager: true }` to `createAppRuntime` in production servers.

4. Replace `errorCaptureMiddleware` with the `reportErrors` observer. Skip this step if you never used it.

   ```ts skip="before and after fragment of a migration"
   // before: core/orpc.ts, then `.use(errorCapture)` on the implementer
   export const errorCapture = errorCaptureMiddleware({
     report: (error, { path }) => captureException(error, { tags: { procedure: path.join('.') } }),
   });

   // after: once, where the app is defined
   defineApp('shop', {
     observers: [
       reportErrors({
         report: (error, { name }) => captureException(error, { tags: { procedure: name } }),
       }),
     ],
   });
   ```

   Delete the `.use(errorCapture)` calls. `bind(logic)` now emits the events, so a procedure needs `bind` to be reported. The rule is the same: an `ORPCError` below 500 is not reported, everything else is, and a reporter that throws is logged and ignored (now on `arki:dot:handlers`, not `arki:dot:orpc`). `name` is the full procedure path joined with dots; the reporter also gets `transport` and `feature`.

## Verify

```sh
cd packages/dot && bun -e "import { resolveDeferred } from '@arki/dot/plugin'; import * as ts from '@arki/ts'; console.log(resolveDeferred(1), resolveDeferred(() => 2), 'resolveLazy' in ts)"
```

It prints `1 2 false`: both forms resolve, and `@arki/ts` no longer exports `resolveLazy`.
