# Upgrade @arki/queue 0.3.0 to 0.4.0

You must act only if a trace query or dashboard expects `queue.execute` to be a child of `dot.unit.start` or to have an internal span kind; everyone else can skip it.

## What changed

- `queue.execute` now starts a new trace when the message carries no producer trace. Before, it fell back to the active context, so in a Dot app every such job nested under the ended `dot.unit.start` span and looked like part of app startup. A message that carries the producer's trace still continues it. `queue.execute` is now a consumer span (`SpanKind.CONSUMER`), matching the producer `queue.enqueue` span.
  
  Docs: README `## Observability`.

## Public API changes

No public API changes.

## Steps

1. Stop expecting `queue.execute` under `dot.unit.start`. A message with no producer trace now starts a new trace. A message that carries the producer's trace still continues it.

   Before:

   ```text
   parent(queue.execute) = dot.unit.start
   ```

   After:

   ```text
   queue.execute is a root span when the message has no producer trace
   ```

2. Match `queue.execute` as a consumer span (`SpanKind.CONSUMER`), like the producer `queue.enqueue` span.

   Before:

   ```text
   span.kind = internal AND name = "queue.execute"
   ```

   After:

   ```text
   span.kind = consumer AND name = "queue.execute"
   ```

## Verify

Run the package tests. They check the span kind and the root trace.

```sh
bun run test
```
