# Upgrade @arki/payments 0.3.2 to 0.4.0

You must act if you call `StripeProvider`, `RefundService`, `SubscriptionManager` or the payments journal commands, use the payment ID factories for tables, or run `defineEnv` in CI. Everyone else can skip it.

## What changed

Breaking:

- Expected payment answers are now returned as `@arki/failure` values, not thrown.
- Provider calls return `CardDeclined`, `IdempotencyConflict` and `ReferenceNotFound`.
- `RefundService` returns refund failures instead of throwing `RefundError`.
- Journal commands return `CommandNotFound`, `CommandConflict` and `CommandInvalid` instead of throwing `CommandError`. Over oRPC the code changes (`NOT_FOUND` becomes `journal.not_found`). The status stays.
- ID generators (`createId`, `createPrefixedId`, factory `create`/`make`/`new`) can return a canonical failure. Payment ID factories no longer carry table helpers.
- `createIdFactory(prefix)` infers its ID from the prefix. The second type argument is gone.
- `defineEnv` validates in every environment. Only `SKIP_ENV_VALIDATION=1` skips it.
- Generated table validators no longer claim `$type<T>` shapes. Use `jsonColumn` with a runtime schema.
- AI types are renamed: `SearchOptionsType` is now `SearchSettings`, and `AIServiceConfigType` is now `RAGServiceConfig`.

Additive:

- The four journal factories (`createCoreJournal`, `createPaymentJournal`, `createSubscriptionJournal`, `createRefundsJournal`) accept any Standard Schema meta with a plain-record output.
- Stripe signatures are checked with `stripe()` from `@arki/http/webhooks`. `@arki/payments` now depends on `@arki/http`. A `t=` that is not Unix seconds now reports `Invalid signature format`.
- A declined card on the last `PaymentRetryService` retry now ends dunning. The subscription is marked past due.
- Docs: README, `llms.txt`, agent guide and `test:docs`.

## Public API changes

- `PaymentProviderErrorCode` loses `card_declined`, `idempotency_conflict` and `reference_not_found`. A card or idempotency error from a call that cannot return those failures is thrown as `invalid_request`.
- New failures in `@arki/payments/core/providers/provider-error`: `CardDeclined` (`payments.card_declined`, 402), `IdempotencyConflict` (`payments.idempotency_conflict`, 409), `ReferenceNotFound` (`payments.reference_not_found`, 404).
- New failures in `@arki/payments/refunds`: `TransactionNotFound`, `RefundWindowExceeded`, `DuplicatePendingRefund`, `RefundAmountExceeded`, `RefundNotFound`, `RefundInvalidState`.
- `RefundErrorCode` keeps only `REASON_REQUIRED` and `PROCESSING_FAILED`.
- `requestRefund`, `approveRefund` and `rejectRefund` return a refund or one of those failures.
- `CoreWrites` and `RefundWrites` return journal failures beside the row.
- `planIdFactory`, `subscriptionIdFactory`, `paymentIdFactory`, `customerIdFactory` and `webhookIdFactory` no longer have `primaryColumn`, `reference` and the other table helpers.

## Steps

1. Branch on returned failures from provider calls. This covers `createSubscription`, `updateSubscription`, `createPayment`, `confirmPayment`, `createPaymentIntent` and `attachPaymentMethod`.

   ```ts
   // before
   try {
     await provider.createPayment(input);
   } catch (error) {
     if (error instanceof PaymentProviderError && error.code === 'card_declined') askForAnotherCard();
   }

   // after
   import { isFailure } from '@arki/failure';
   import { CardDeclined } from '@arki/payments/core/providers/provider-error';

   const result = await provider.createPayment(input);
   if (isFailure(result) && CardDeclined.is(result)) askForAnotherCard();
   ```

2. Branch on returned refund failures. Remove `catch` blocks that read `RefundError` codes other than `REASON_REQUIRED` and `PROCESSING_FAILED`.

   ```ts
   // before
   try {
     await refunds.requestRefund(data);
   } catch (error) {
     if (error instanceof RefundError && error.code === 'WINDOW_EXCEEDED') showWindowMessage();
   }

   // after
   import { isFailure } from '@arki/failure';
   import { RefundWindowExceeded } from '@arki/payments/refunds';

   const refund = await refunds.requestRefund(data);
   if (isFailure(refund) && RefundWindowExceeded.is(refund)) showWindowMessage();
   ```

3. Handle journal failures where you call `SubscriptionManager`, `DunningService`, `CoreWrites` or `RefundWrites`. They now return the refusal instead of throwing `CommandError` or `Error('Failed to ...')`. If you register oRPC error maps, use `journal.not_found`, `journal.conflict` and `journal.invalid` in place of `NOT_FOUND`, `CONFLICT` and `BAD_REQUEST`.

4. Check ID generation results before you use them. `createId` and the payment `create*Id` functions can return an ID generation failure.

   ```ts
   const id = createPaymentId();
   if (isFailure(id)) return id;
   ```

5. Build tables with `idColumns` instead of the factory's own helpers.

   ```ts
   // before
   id: planIdFactory.primaryColumn(),

   // after
   import { idColumns } from '@arki/db/id';

   id: idColumns(planIdFactory).primaryColumn(),
   ```

6. Remove the second type argument from `createIdFactory(prefix)`. The ID type comes from the prefix.

7. Rename the AI types: `SearchOptionsType` to `SearchSettings`, `AIServiceConfigType` to `RAGServiceConfig`.

8. If a build stage has no secrets, set `SKIP_ENV_VALIDATION=1` for it. `defineEnv` no longer skips validation in `CI` or lint runs.

## Verify

```sh
bun run typecheck
```

Run it in your app. It passes only when every returned failure is handled and every renamed or removed name is gone.
