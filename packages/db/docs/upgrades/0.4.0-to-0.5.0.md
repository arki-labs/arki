# Upgrade @arki/db 0.4.0 to 0.5.0

Act on this if you call `migrateDb`, `pendingMigrations` or `readMigrations` yourself, or use the `MigratableDb` or `TransactionalDb` types. Apps that only use the `db()` Dot plugin and `dbMigrations()` can skip the steps.

## What changed

- The column kit: a package writes each table once, against `ColumnKit<D>` (`@arki/db/columns`), and the app passes `pgColumns(schema?)` (`@arki/db/pg`) or `sqliteColumns({ prefix? })` (`@arki/db/sqlite`). Kit tables have exactly the types of hand-written `pgTable` / `sqliteTable` tables, and on Postgres drizzle-kit sees no difference, so moving tables to the kit needs no migration. On SQLite, `varchar(n)` / `char(n)` keep their limit as a `length()` `CHECK`, and index names take the prefix. `@arki/db/sqlite` also gains `instant`, a `Temporal.Instant` column stored as integer milliseconds. The kit's `serial(name?)` is an auto-incrementing primary key (`bigserial` on Postgres, `integer primary key autoincrement` on SQLite), and `@arki/db/sqlite` exports `sqliteNowMs`, the database clock in milliseconds.
- A browser-safe `@arki/db/contract` entry, so an oRPC contract that ships to the browser never bundles drizzle-orm or a Postgres driver. It holds `TRANSACTION_FAILURES`, the six transaction failures (`TransactionConflict`, `TransactionUnavailable`, `TransactionRejected`, `TransactionCommitUncertain`, `TransactionCancelled`, `TransactionDefect`) and the type `TransactionFailure`. Ids for a contract come from `defineId` in `@arki/contracts`.
- Hosted Postgres behind a connection pooler (Neon, Supabase, PlanetScale Postgres, self-hosted PgBouncer). The `db()` plugin takes a `directUrl` thunk, falling back to the new `DB_DIRECT_URL` env var, and publishes `sessionPool`: a small pool on the direct URL for `LISTEN`, session locks and migrations. On a known pooled `DB_URL` (Neon `-pooler`, Supabase port `6543`) with no direct URL, the app still boots, and `sessionPool.connect()` rejects with `ARKI_DB_PLUGIN_E004` naming the host and the fix. `@arki/db/pg` exports `pooledHostOf`, `resolveDirectUrl`, `POOLED_HOSTS` and the `db.session_needs_direct_url` failure for apps without Dot. CockroachDB is checked by an opt-in test (`ARKI_DB_CRDB=1`): queries, `40001` retries, unique-violation errors and migrations work; `LISTEN` does not.
- Return precise canonical outcomes from migration source reads, state inspection and application. Preserve unwrapped success, stop Dot boot on refusal and report unconfirmed application without automatic retry. Validate native bookkeeping rows through their source schema and expose original failure declarations through the browser-safe contract entry.
  
  Default migration spans preserve caller context and keep paths, SQL and private causes out of telemetry. Observe rejected telemetry acquisition and reserve synchronous execution as well as existing asynchronous ownership. Process/test callers handle migration failures explicitly. See the migration outcome upgrade guide; no demo impact because demos use the existing Dot boundary.
- SQLite through libSQL. `db({ driver: 'libsql', url })` and `createLibsqlDb` (`@arki/db/libsql`) open a local file, `:memory:` or a Turso / libSQL server; `@libsql/client` is an optional peer. `@arki/db/sqlite` re-exports `drizzle-orm/sqlite-core` and adds `idColumns`. `runTransaction`, `createUnitOfWork`, `isUniqueViolation`, `migrateDb`, `pendingMigrations` and `dbMigrations()` work on it: SQLite errors read as SQL-standard SQLSTATEs (`SQLITE_BUSY` is the retryable `40001`), and local writers take turns instead of failing with `SQLITE_BUSY`. New: `dialectOf`, `isTransaction`, `isLibsql`; `ARKI_DB_TX_E007` refuses SQLite drivers other than libSQL; `ARKI_DB_PLUGIN_E005` catches a URL that belongs to the other driver. `TransactionalDb`'s config is now `TransactionConfig` (`PgTransactionConfig & SQLiteTransactionConfig`), and `runTransaction` passes `{ isolationLevel: 'serializable', behavior: 'immediate' }`. `MigratableDb` now includes `LibSQLDatabase`: code that used it as its own query handle should name its driver's database type.

## Public API changes

Changed:

- `readMigrations`, `pendingMigrations` and `migrateDb` return failures as values instead of throwing. `migrateDb` resolves to `undefined` on success, or to a source failure, `MigrationUnconfirmed` or `UnexpectedDefect`.
- `MigratableDb` now also includes `LibSQLDatabase`.
- `TransactionalDb` takes `TransactionConfig` (`PgTransactionConfig & SQLiteTransactionConfig`).

Added:

- Entries `@arki/db/libsql`, `@arki/db/sqlite`, `@arki/db/columns` and the browser-safe `@arki/db/contract`.
- `db({ driver: 'libsql', url })`, `createLibsqlDb`, `dialectOf`, `isTransaction`, `isLibsql`.
- Pooler support: the `directUrl` option, the `DB_DIRECT_URL` env var and the `sessionPool` service; `pooledHostOf`, `resolveDirectUrl`, `POOLED_HOSTS` in `@arki/db/pg`.
- Error codes `ARKI_DB_TX_E007`, `ARKI_DB_PLUGIN_E004`, `ARKI_DB_PLUGIN_E005`.

## Steps

1. Upgrade the package:

   ```sh
   bun add @arki/db@^0.5.0
   ```

2. Handle the migration result. A refused migration no longer throws.

   ```ts skip="before: the 0.4.0 API"
   // before
   await migrateDb(db, { migrationsFolder: './drizzle' });

   // after: in service code, return the failure to your caller
   import { isFailure } from '@arki/failure';
   const migrated = await migrateDb(db, { migrationsFolder: './drizzle' });
   if (isFailure(migrated)) return migrated;

   // after: in a script or test, fail the process
   import { orThrow } from '@arki/failure';
   orThrow(await migrateDb(db, { migrationsFolder: './drizzle' }));
   ```

   Do the same for `pendingMigrations` and `readMigrations`. A failed apply is not retried and does not prove a rollback: check the schema before you run it again. See [migration-outcomes.md](./migration-outcomes.md).

3. If you used `MigratableDb` as your query handle, name your driver's database type instead, because the union now includes libSQL.

   ```ts skip="before: the 0.4.0 API"
   // before
   function listUsers(db: MigratableDb) {}

   // after
   import type { NodePgDatabase } from 'drizzle-orm/node-postgres';
   function listUsers(db: NodePgDatabase) {}
   ```

4. If you implemented `TransactionalDb` yourself, accept `TransactionConfig` in place of the Postgres-only config.

5. Optional, for Neon, Supabase or PgBouncer: set `DB_DIRECT_URL` to the direct (non-pooled) connection string, so `LISTEN`, session locks and migrations use it.

## Verify

```sh
bun run typecheck && bun run test
```

Both pass once every call site handles the returned result. In tests, a refused migration now fails through `orThrow` with its failure code.
