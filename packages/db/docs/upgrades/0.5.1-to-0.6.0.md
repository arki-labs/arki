# Upgrade @arki/db 0.5.1 to 0.6.0

You must act if you call `createIdFactory`, or start a Postgres listener (`listenOnPool`, `worker.start()`, `hub.start()` or a pg `subscribe()`); everyone else can skip it.

## What changed

- Removed `createIdFactory` from `@arki/db`. Its id type came from the prefix alone, so two kinds with the same prefix were interchangeable. Migration: declare the id with `defineId(prefix)` from `@arki/contracts` and get its columns with `idColumns(declaration)` from `@arki/db/id`. Replace `make()` and `new()` with `create()`. `createId` and `createPrefixedId` stay. The `dot new` stack template now declares its note id this way and adds `@arki/contracts` to the generated `package.json`.
- A Postgres listener that cannot start now returns its failure instead of rejecting.
  
  - `@arki/db`: `listenOnPool(pool, channel)(onMessage)` resolves to `ListenUnavailable` (`db.listen_unavailable`) when the first connection or `LISTEN` fails. It no longer rejects with an `UnexpectedFailure`. The raw pool error stays its private `cause`. Nothing retries: call the start again.
  - `@arki/journal`: a `WakeListener` may return a `Failure`. `worker.start()` resolves to that failure and leaves the worker stopped, so a later `start()` tries again. A `listen` that throws also leaves it stopped (before, the worker stayed marked running and every later `start()` did nothing). The failure type is inferred: a worker without `listen` returns no failure. In Dot, `journalWorker()` returns the failure from `start`, so the app's start fails with it.
  - `@arki/pubsub`: `PubSub` and `TransactionalPubSub` take a `SubscribeFailure` type (`never` by default). `pgPubSub`'s `subscribe` resolves to `db.listen_unavailable` when the channel's listener cannot start; nothing stays subscribed, and the next `subscribe` tries again.
  - `@arki/live`: a `LiveSource`'s `start` may return a failure, and `hub.start()` resolves to it (`pgSource`: `db.listen_unavailable`). The hub stays `idle` and stopped, so a later `hub.start()` on the same hub tries again; a successful start happens once. `liveQueries()` returns it from its Dot `start`.
  
  Upgrade: check the result of `worker.start()`, `hub.start()` and pg `subscribe()` where a listener is wired, for example `orThrow(await worker.start())` in a script, or return it from a Dot `start` hook.

## Public API changes

Removed:
- `createIdFactory` from `@arki/db/id` (function)
- `createIdFactory` from `@arki/db/id-factory` (function)

Changed:
- `listenOnPool` from `@arki/db/pg`
  - before: `export declare function listenOnPool(pool: ListenPool, channel: string, options?: ListenOptions): (onMessage: (payload: string) => void) => Promise<() => Promise<void>>;`
  - after: `export declare function listenOnPool(pool: ListenPool, channel: string, options?: ListenOptions): (onMessage: (payload: string) => void) => Promise<(() => Promise<void>) | ReturnType<typeof ListenUnavailable>>;`

## Steps

1. Replace `createIdFactory` with `defineId` from `@arki/contracts` and `idColumns` from `@arki/db/id`. Replace `make()` and `new()` with `create()`. `createId` and `createPrefixedId` stay.

   Before:

   ```ts skip="before: the 0.5.1 API"
   import { createIdFactory } from '@arki/db/id';

   const noteId = createIdFactory('note');
   const id = noteId.make();
   ```

   After:

   ```ts skip="the 0.6.0 API; the example needs @arki/contracts"
   import { defineId } from '@arki/contracts';
   import { idColumns } from '@arki/db/id';

   const noteId = defineId('note_');
   const columns = idColumns(noteId);
   const id = noteId.create();
   ```

   `create()` returns an ID or `IdGenerationFailure`. Check it with `isFailure` from `@arki/failure` before you use it.

2. Check the result where you wire a Postgres listener. A listener that cannot start now returns `ListenUnavailable` (`db.listen_unavailable`) instead of rejecting. Nothing retries. Call the start again.

   Before:

   ```ts skip="before: the 0.5.1 API"
   await worker.start();
   ```

   After:

   ```ts skip="the 0.6.0 API; the example needs a running worker"
   import { orThrow } from '@arki/failure';

   orThrow(await worker.start());
   ```

   Do the same for `hub.start()` and for pg `subscribe()`. In a Dot app, return the failure from your `start` hook.
