# Upgrade @arki/db 0.3.1 to 0.4.0

Act on this if you create IDs with `createIdFactory`, open a PGlite data directory, or use `defineEnv` in CI or lint runs. Skip it if you only use `createDb({ url })` with a normal Postgres pool.

## What changed

Added in 0.4.0 (no action needed):

- `@arki/db/dot`: `repos`, `txRepos`, `transactions(handle)` (plugins for a feature's repositories and transactions).
- `@arki/db/pagination`: `keysetQuery(keyset, columns)`.
- `@arki/db/id`: `idColumns`.
- `@arki/db/errors`: `isUniqueViolation(error, constraint?)`.
- `@arki/db/transaction`, `@arki/db/orpc`, `@arki/db/eslint`: `runTransaction`, `transactionalProcedure`, and the `db/no-effects-in-transaction` rule.
- `@arki/db/migrate`: `pendingMigrations(db, options)`.
- `@arki/db/orm`: `mergeRelations`.
- `@arki/db/pg`: `listenOnPool` (it moved here from `@arki/journal`).
- `createDb({ url })` no longer needs `DB_URL` set.

Breaking changes are in the next sections.

## Public API changes

- `createIdFactory<TPrefix, TId>(prefix)` is now `createIdFactory<TPrefix>(prefix)`. The ID type comes from the literal prefix. The old second type argument is gone.
- The ID `create`, `make` and `new` functions now return an ID or a canonical failure. They no longer return a plain ID.
- `initDbRuntimeLocal` (and `db({ driver: 'pglite', dataDir })`) now takes an owner lock at `<dataDir>/.arki-owner`. A second open on the same directory throws `DbRuntimeLocalError` with code `ARKI_DB_LOCAL_E001`. Both are exported from `@arki/db/runtime-local`.
- `defineEnv` now validates in every environment, including CI and lint.
- Generated table validators no longer carry phantom `$type<T>` shapes.

## Steps

1. Remove the second type argument of `createIdFactory`.

   Before:

   ```ts skip="before: the 0.3.1 API"
   const poetId = createIdFactory<'pt', PoetId>('pt');
   ```

   After:

   ```ts
   import { createIdFactory } from '@arki/db/id';

   const poetId = createIdFactory('pt');
   ```

2. Check every generated ID before you use it. Import `isFailure` from `@arki/failure`.

   Before:

   ```ts skip="before: the 0.3.1 API"
   const id = createPoetId();
   ```

   After:

   ```ts
   import { createIdFactory } from '@arki/db/id';
   import { isFailure } from '@arki/failure';

   const createPoetId = createIdFactory('pt').create;

   export function newPoetId() {
     const id = createPoetId();
     if (isFailure(id)) return id; // return or handle the failure
     return id;
   }
   ```

   Stored IDs and prefixes are unchanged. Take stored types from the factory `schema`, not from `ReturnType` of `create`.

3. Check the result of `initDbRuntimeLocal` the same way. It can now return a canonical failure. Use `isFailure` before you use the database.

4. Make sure only one handle opens each PGlite directory. Two handles on one directory used to open (and could corrupt data). The second now throws `ARKI_DB_LOCAL_E001`. Close the first handle with `pglite.close()` first. `memory://` and `idb://` take no lock.

5. Give `defineEnv` real values in CI and lint, or opt out in a build stage that has no secrets.

   ```sh
   # before: CI and lint skipped validation
   # after: set only where secrets are missing (exactly 1)
   SKIP_ENV_VALIDATION=1
   ```

6. If you relied on a `$type<T>` shape in a generated validator, use a runtime schema with `jsonColumn` from `@arki/contracts/drizzle` and reuse it in your validator refinement. Bare JSON columns keep the native validator.

## Verify

```sh
bun run typecheck
```

Run it in your app. It must show no errors from `createIdFactory` or from using an ID before checking it. Then run your tests with real env values: `defineEnv` no longer skips validation in CI.
