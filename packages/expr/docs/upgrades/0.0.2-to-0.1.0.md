# Upgrade @arki/expr 0.0.2 to 0.1.0

Parsers of outside values return, builders throw.

- `evaluate(text)` from `@arki/expr/float`, `/decimal`, `/rational` and `/complex` returns the value or a failure: `InvalidExpression` (`expr.invalid_text`), `ExpressionOverBudget` (`expr.over_budget`) or `NoValue` (`expr.no_value`). Replace `try { evaluate(text) } catch (error) { … }` with `const value = evaluate(text); if (isFailure(value)) { … value.cause … }`. `cause` is the error that used to be thrown, so code that read `ParseError.span` or matched `DivisionByZeroError` reads `value.cause`.
- `syntaxFor(locale)` returns `InvalidLocale` for a tag `Intl` rejects. It no longer throws `UnsupportedFeatureError` on Hermes: it reads the decimal mark with `format`.
- New `parseSyntax(value: unknown)` reads stored settings and returns `InvalidSyntax`. `defineSyntax` stays the throwing builder.
- `parse`, `parseEquation` and `fromJSON` return the tree or `InvalidExpression` (`expr.invalid_text`) or `ExpressionOverBudget` (`expr.over_budget`); the list is `PARSE_FAILURES`. `cause` is the `ParseError` (with `span`, `code`, `expected`, `found`) or `ExprLimitError` that used to be thrown. Replace `try { parse(text) } catch (error) { if (error instanceof ParseError) … }` with `const expr = parse(text); if (isFailure(expr)) { … expr.cause … }`. For text your own code wrote, use `orThrow(parse(text))` from `@arki/failure`. A non-string `text` and a language not built by `defineLanguage` are bugs and still throw; `fromJSON` now throws `InvalidArgumentError` (not `ParseError`) for such a language.
- `compile`, `compileEquation` and compiled functions take a tree or definition that code built, so they still throw `ParseError` (`unknown-name`, `name-conflict`, `not-in-domain`, `arity`), `ExprLimitError` and the `@arki/math` errors. Because `compile` takes an `Expr`, `compile(parse(text))` no longer type-checks until you handle the failure.
- `@arki/failure` is a new runtime dependency.
