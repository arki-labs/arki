# Upgrade @arki/expr 0.0.2 to 0.1.0

Parsers of outside values return, builders throw.

- `evaluate(text)` from `@arki/expr/float`, `/decimal`, `/rational` and `/complex` returns the value or a failure: `InvalidExpression` (`expr.invalid_text`), `ExpressionOverBudget` (`expr.over_budget`) or `NoValue` (`expr.no_value`). Replace `try { evaluate(text) } catch (error) { … }` with `const value = evaluate(text); if (isFailure(value)) { … value.cause … }`. `cause` is the error that used to be thrown, so code that read `ParseError.span` or matched `DivisionByZeroError` reads `value.cause`.
- `syntaxFor(locale)` returns `InvalidLocale` for a tag `Intl` rejects. It no longer throws `UnsupportedFeatureError` on Hermes: it reads the decimal mark with `format`.
- New `parseSyntax(value: unknown)` reads stored settings and returns `InvalidSyntax`. `defineSyntax` stays the throwing builder.
- `parse`, `parseEquation`, `fromJSON`, `compile` and compiled functions still throw `ParseError`, `ExprLimitError` and the `@arki/math` errors.
- `@arki/failure` is a new runtime dependency.
