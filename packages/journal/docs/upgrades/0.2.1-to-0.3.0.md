# Upgrading command and durable outcomes

1. Narrow the inferred command result before using its successful value.
   `CommandFailure` derives from `COMMAND_FAILURES`; combine these original
   definitions with the command's domain failures at native RPC boundaries.
2. Remove exception translation around receipt conflicts from `journal.run`.
   A reused receipt key with a different command or input returns
   `CommandConflict`. Authorization still runs before a receipt replay.
3. Return refusals from handlers, authorization and event callbacks. A refusal
   rolls back writes and leaves no successful receipt. If a nested operation
   refuses, propagate its failure or call `accept` on that exact returned
   instance once. Ignoring it and reporting success dooms the command.
4. Managed command exceptions use the shared transaction failures. Unknown
   exceptions become `TransactionDefect`; recognized database rejections,
   failed rollbacks and uncertain commits retain their distinct definitions.
   Durable effect and workflow callback exceptions become `UnexpectedDefect`.
   Original causes remain private. Defects stop durable work by default; only
   an explicit retry predicate may select a failure. Static definition misuse
   still fails loudly; runtime acceptance misuse rolls back as a typed defect.
5. Return a queue runner's outcome from `JobRunner.run`. Journal classifies a
   returned failure before acknowledging the job; `retryDelay` receives the
   original refusal. Do not wrap a failure inside a success object.
6. Handle canonical `Deadline` for workflow step timeouts and
   `WorkflowStranded` for missing or structurally incompatible pinned code.
   Keep the old name/version registered until existing runs finish. Restore
   matching code before retrying a stranded job.
7. Bump the workflow version whenever handler semantics change. A structural
   graph hash cannot detect a semantic edit that keeps the same node names.
   Persisted step identity, fencing, waits and cancellation remain authoritative
   during recovery.

External effects run at least once. Send a stable step/job idempotency key to the
external system. A lost transaction commit acknowledgement remains uncertain;
reconcile it through the receipt instead of assuming rollback or retrying with
a fresh key.

This migration covers owned command and durable execution outcomes. The separate
export audit tracks remaining low-level driver/lifecycle exceptions and
Journal-native OpenTelemetry coverage; it does not claim all exports are already
migrated.
