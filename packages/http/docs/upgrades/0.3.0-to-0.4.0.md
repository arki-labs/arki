# Upgrade @arki/http 0.3.0 to 0.4.0

Act if you call `requestContext()` from `@arki/http/context`, use `derive` or `.derive(...)`, or pass `engine.fetch` where an engine would do. Skip it if you only declare routes and serve them with `http()` or `listen`.

## What changed

Breaking:

- `requestContext()` needs an engine built with `{ requestContext: true }` (`buildEngine(bundles, { requestContext: true })`, or `http({ requestContext: true })` in a Dot app). Without it no request enters the store, and calling `requestContext()` in a process whose engines all left it off throws `ARKI_HTTP_E014`. Outside any engine it still returns `undefined`.

- `derive(key, fn)`, the bundle's `.derive(...)`, `Deriver`, `ErasedDeriver`, `BASE_CTX_KEYS` and `ARKI_HTTP_E007` are gone. Write a step: `.derive('principal', req => verify(req))` becomes `.use(step(async ({ req }: BaseRequestCtx) => { const p = await verify(req); return isFailure(p) ? p : { principal: p }; }))`. A step reads the context (`req` is on it) and returns an object to add, or a failure. `failureHeaders` moves to `step(fn, { failureHeaders })`.
- `verifyWebhook({ scheme })` is a step: it takes the context and returns `{ webhook }` or a failure. Use `routes().use(step(verifyWebhook({ scheme })))`. A direct call passes `{ req }`.

Added (no action needed):

- `buildEngine` routes with its own compiled router and keeps Hono behind it for mounts, rpc mounts, `:x?` and `*` paths; `buildHonoEngine` is the Hono-only engine.
- `listen(engine, options)` takes an engine and hands its `bunRoutes` to `Bun.serve({ routes })`; `listen(fetch, options)` still works.
- `composeMiddleware(engine, middleware)` wraps an engine, Bun route handlers included, and returns an engine.
- Zod schemas are compiled once with `z.compile()`; the request context parses `url` on first read.
