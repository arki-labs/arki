# 0.1.3 to 0.2.0

Owned storage adapters, file lifecycle methods and uploadFile now return exact canonical failures.
Check `isFailure(result)` and forward the failure before using the success value. Do not throw returned
failures into generic retry loops. Reconcile `StorageWriteUncertain` against the object or durable row;
the S3 SDK no longer automatically retries requests after acknowledgement loss.

Wrap native oRPC upload clients with `filesUploadClient` from `@arki/fs/orpc`. Custom `UploadClient`
implementations return the canonical failure sets themselves. Operation-invalid input returns
`SCHEMA_FAILURES`; static construction/configuration faults still throw. Cleanup returns an exact failure
while preserving durable backoff duty; success has `failed: 0`.

Local keys must be relative and contain no dot segments, backslashes, NUL or empty path segments.
Descendant symlinks are refused. Keep the resolved base directory application-owned. `readFirstLine`
returns `undefined` on empty EOF and canonical failures on missing/error/cancel; callers must handle them.
The raw native reexports, legacy Flystorage handle and older synchronous readFile helper retain their
existing foreign/native contracts and are not evidence that the package migration is complete.
