# Upgrade @arki/auth 0.4.0 to 0.5.0

You must act if you import `emailModuleMock` from `@arki/auth/testing/production-boot`, or if you use `IntegrationTester` or `initTester` (now here, moved from `@arki/testing`); everyone else can skip it.

## What changed

- `@arki/auth/testing/integration-tester`: the connection, event-store, id and page checks use schemas (A-39), and caller values the tester cannot honour are the invariant failure `ARKI_FAILURE_E008` before any work runs.
  
  - `clearTables`, `clearAllTables`, `clearTablesExcept` and `clearTablesByPattern` refuse a set that leaves out a schema table referencing a cleared one (without `on delete cascade` / `set null`), naming it, before deleting any row (was a raw 23503 half-way through). `clearTablesByPattern` ignores a RegExp's `g` / `y` flags (they skipped tables) and refuses a string that is not a regular expression (was a raw `SyntaxError`).
  - `generateBetween` takes whole numbers with `min <= max` (fractions and reversed bounds returned values outside the range); `generateDate` refuses an `Invalid Date` bound (was a raw `RangeError`), `from` after `to`, and a negative, non-finite or out-of-range span; `generateString` takes a length from 0 to 64 (longer was silently cut); `generateFromEnum` refuses an empty list (returned `undefined`); `waitForProjections` takes 0 to 2^31 - 1 ms.
  - `assertPaginatedResponse` now delegates to `assertPaginationValid` from `@arki/testing` and narrows to its `PaginatedResponse`, so `total`, `nextCursor` and `hasMore` types are checked when present.
- Breaking: `emailModuleMock` is removed from `@arki/auth/testing/production-boot`. Booting an auth sends no mail, so a production-boot test no longer needs to mock `@arki/mail`. Build the real mail transport with a placeholder key (for example `process.env.RESEND_API_KEY ??= 'test_resend_key'`) and delete the `vi.mock('@arki/mail', ...)` block. A test that checks mail content should send through `@arki/mail/http/mailpit` to a Mailpit container (`@arki/testing/containers/mailpit`) and read the mailbox. `assertAuthBoots` and `applyProductionBootEnv` are unchanged, and `vitest` stays an optional peer because `assertAuthBoots` uses `expect`.
- New entry `@arki/auth/testing/integration-tester`: `IntegrationTester`, `initTester` and their types (`TestUser`, `TestUserRole`, `TesterOptions`, `TesterUsers`, `TesterUserOverrides`, `TesterDatabase`, `IntegrationTesterConfig`, `CreateCallerArgs`, `TesterBuilder`, `TesterConfig`, `ContextTesterBuilder`, `InitialTesterBuilder`). They moved here from `@arki/testing/server/integration-tester` and `@arki/testing/server/tester-builder`, unchanged, because their test users carry an auth `UserId`. Change the import path only. The entry needs the new optional peers `@arki/testing`, `testcontainers` and `@testcontainers/postgresql`, and Docker unless a global connection string is set.
  
  Docs: README `## Public imports` and `## Documentation`, new `docs/integration-tester.md`, `docs/agent-guide.md`.

## Steps

1. Delete `emailModuleMock` and the `vi.mock('@arki/mail', ...)` block. Booting an auth sends no mail. Build the real mail transport with a placeholder key.

   Before:

   ```ts skip="before: the 0.4.0 API"
   import { emailModuleMock } from '@arki/auth/testing/production-boot';

   vi.mock('@arki/mail', emailModuleMock);
   ```

   After:

   ```ts skip="the 0.5.0 setup; the example runs inside a vitest file"
   process.env.RESEND_API_KEY ??= 'test_resend_key';
   ```

   A test that checks mail content sends through `@arki/mail/http/mailpit` to a Mailpit container and reads the mailbox.

2. If you used the tester from `@arki/testing`, import it from `@arki/auth` instead. The names and types are the same. Add the optional peers `@arki/testing`, `testcontainers` and `@testcontainers/postgresql`. You need Docker unless you set a global connection string.

   Before:

   ```ts skip="before: the 0.4.0 API"
   import { initTester } from '@arki/testing/server/tester-builder';
   ```

   After:

   ```ts skip="the 0.5.0 import path; the example needs Docker"
   import { initTester } from '@arki/auth/testing/integration-tester';
   ```

3. Check the arguments you pass to the tester helpers. A value the tester cannot honour (a reversed `generateBetween` range, an empty `generateFromEnum` list, a bad `clearTables` set) fails with the invariant failure `ARKI_FAILURE_E008` before any row is touched. The "What changed" list names each rule.


## Verify

```sh
bun run typecheck
```

Run it in your app. It passes only when no file imports `emailModuleMock` or the old tester paths. Then run your production-boot test: it must pass with no `vi.mock('@arki/mail', ...)`.
