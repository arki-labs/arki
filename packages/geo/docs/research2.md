# Best Geocoding Libraries for TypeScript and Node.js

**node-geocoder remains the dominant choice with 70,000 weekly downloads, but three TypeScript-native alternatives now offer superior developer experience**: @goparrot/geocoder for multi-provider flexibility, @googlemaps/google-maps-services-js for Google Maps users, and opencage-api-client for OpenCage devotees. For production forward geocoding, the best free option combines node-geocoder with OpenStreetMap/Nominatim (1 req/sec limit) or LocationIQ's generous 60,000 requests/month free tier. When TypeScript quality matters most, choose libraries written natively in TypeScript rather than JavaScript libraries with type definitions.

The geocoding library landscape has matured significantly, with TypeScript-first implementations now matching the feature completeness of older JavaScript libraries. **Multi-provider support is critical for production resilience**—services like Google Maps impose strict 30-day caching limits and require displaying results on Google maps, while OpenCage, Geocodio, and LocationIQ allow permanent data storage. For North American addresses specifically, Geocodio delivers exceptional value at $0.50 per 1,000 requests with included Census data enrichment, while global applications benefit most from LocationIQ's aggressive pricing ($0.017 per 1K at high volume) or HERE's remarkably generous 250,000 free requests monthly.

## Top production-ready libraries compared

The research identified seven production-ready libraries with distinct strengths. **node-geocoder dominates adoption** despite inactive maintenance since November 2021, processing millions of geocoding requests daily across 18 provider integrations. The library's stability has proven more valuable than cutting-edge features—its 947 GitHub stars and 70,000 weekly NPM downloads reflect deep production entrenchment. However, TypeScript developers now have better options.

**@goparrot/geocoder emerged as the best TypeScript-native multi-provider solution**, written entirely in TypeScript with full type safety across 15+ geocoding providers. Unlike node-geocoder's community-maintained type definitions, @goparrot/geocoder provides native types as authoritative documentation. The library implements sophisticated provider patterns: ChainProvider automatically falls back through multiple services until success, while ProviderAggregator allows runtime provider selection. Advanced features include autocomplete suggestions (Google, HERE), distance calculations with travel modes, and place details enrichment. The architecture uses dependency injection with Axios, enabling request/response interceptors for caching and logging. Active maintenance through July 2024 ensures compatibility with modern TypeScript projects, though the library requires reflect-metadata and has lower adoption than node-geocoder.

**For Google Maps users exclusively**, @googlemaps/google-maps-services-js delivers the definitive TypeScript experience. Google rewrote this library natively in TypeScript (source files are .ts, not JavaScript), making types the authoritative API documentation. IntelliSense support is exceptional with comprehensive JSDoc comments, full type inference, and enum constants for languages and travel modes. The async/await Promise-based API eliminates callbacks entirely, with Axios providing HTTP transport. This replaced the deprecated @google/maps library with dramatically improved TypeScript ergonomics. Google's official support and regular updates make this the safest choice for Google Maps integration, though it's server-side only and locks you into Google's ecosystem.

**opencage-api-client stands out for single-provider excellence**, built natively in TypeScript with ESM, CommonJS, and UMD module support. The library receives active maintenance (last update within days of research) and includes comprehensive tutorials with rate-limiting patterns. OpenCage aggregates OpenStreetMap, Nominatim, GeoNames, and other open sources, providing permissive data terms—you can store results permanently even after canceling subscriptions. The free trial offers 2,500 requests daily at 1 req/sec, with paid plans starting at $50/month for 10,000 daily requests. Browser and Node.js support makes this library uniquely versatile, while AbortSignal support enables request cancellation. Documentation quality exceeds alternatives with extensive tutorials and clear API references.

**Mapbox's official @mapbox/mapbox-sdk** delivers comprehensive mapping platform integration beyond geocoding. While not TypeScript-native, the DefinitelyTyped definitions provide very good type coverage. The SDK's strength lies in cohesive service integration: geocoding, directions, styles, tilesets, and maps all share consistent patterns. The MapiRequest/MapiResponse architecture with send() methods, pagination support, and progress events creates a modern developer experience. Cross-platform support (Node.js, browsers, React Native) makes this valuable for mobile applications. However, Mapbox's permanent geocoding API requires expensive enterprise licensing—the standard temporary geocoding ($0.50 per 1K) prohibits result caching. Choose Mapbox when beautiful custom maps matter as much as geocoding accuracy.

**universal-geocoder prioritizes platform agnostics**, running identically in Node.js, browsers, React Native, and Electron. This TypeScript fork of GeocoderJS maintains compatibility with older browsers through polyfills while supporting modern async/await. The query builder pattern (GeocodeQuery and ReverseQuery classes) creates fluent APIs with method chaining. Built-in GeoJSON export standardizes output format across providers. The ChainProvider implementation enables fallback strategies across 9 geocoding services. Documentation quality is strong with a dedicated site and clear examples, though maintenance has been limited since June 2021.

**@aashari/nodejs-geocoding wins for minimalism**—zero dependencies, tiny bundle size, full TypeScript support. This lightweight wrapper around Google's geocoding API provides simple encode/decode functions with multilingual support. The author explicitly positions this for non-commercial, low-volume use, making it ideal for prototypes and internal tools but unsuitable for production applications requiring SLAs.

## Provider support and integration patterns

The multi-provider libraries support overlapping but distinct provider sets. **node-geocoder offers the broadest coverage** with 18 providers: Google Maps, HERE, Mapbox, MapQuest, Bing, TomTom, OpenStreetMap/Nominatim, OpenCage, LocationIQ, ArcGIS, Geocodio, PickPoint, Yandex, APlace.io, DataScienceToolkit, OpenDataFrance, Teleport, and SmartyStreets. Configuration follows a simple options pattern specifying provider name and API key. The library abstracts provider-specific parameters behind a unified interface, though some providers may use outdated API versions given the inactive maintenance.

**@goparrot/geocoder supports 15+ providers** with a more sophisticated architecture. Provider classes inherit from base interfaces, enabling type-safe configuration. The library distinguishes between geocode, reverse, suggest, place details, and distance operations—not all providers support all operations. Google Maps provides complete feature coverage including suggestions and place details, while HERE supports most operations except place details. OpenStreetMap and Mapbox handle basic geocoding and reverse geocoding only. The ChainProvider and ProviderAggregator patterns enable resilient architectures that automatically failover between services.

**Provider-specific official SDKs** excel when using a single service exclusively. Google's @googlemaps/google-maps-services-js covers the complete Google Maps Platform: geocoding, places, directions, distance matrix, elevation, and timezone APIs. Mapbox's SDK similarly integrates geocoding with their broader platform. These official implementations receive priority bug fixes and feature updates, making them more reliable than multi-provider libraries' implementations. However, vendor lock-in increases migration costs if you later need to switch providers.

## Free tier limits and pricing optimization

**Geocoding pricing varies dramatically by provider and usage tier**. OpenStreetMap/Nominatim offers truly unlimited free geocoding with a 1 request per second rate limit and usage policy requiring attribution. This community-run service works well for low-volume applications but lacks SLAs and may experience variable response times. Self-hosting Nominatim removes rate limits but requires server infrastructure.

**LocationIQ provides the most generous free tier for production use**—60,000 requests monthly with 2 req/sec limits and required attribution links. The free tier suits small commercial applications, while paid tiers scale affordably: $47/month for 10,000 daily requests (300K/month), $100/month for 50,000 daily (1.5M/month), and $500/month for 1 million daily requests (30M/month). The 20 req/sec rate limit on paid plans handles traffic spikes well. LocationIQ's startup program offers 50% discounts for companies under two years old.

**HERE's 250,000 free monthly transactions** represent exceptional value for applications with variable usage. Unlike daily limits that reset, monthly quotas accommodate spikey workloads—perfect for seasonal businesses or B2B applications with concentrated usage periods. Paid pricing starts at $1 per 1,000 requests up to 5 million monthly, decreasing to $0.66 per 1K beyond 10 million. HERE's daily map updates and strong logistics focus make this ideal for fleet management and delivery applications.

**Google Maps offers $200 monthly credit** covering approximately 28,500 geocoding requests at $5 per 1,000 (volume discounts reduce this to $4 per 1K). However, Google imposes the strictest data retention terms: results may only be cached 30 days maximum and must be displayed on Google maps. These restrictions make Google unsuitable for analytics applications requiring permanent storage. The 3,000 queries per minute rate limit handles high-volume applications well.

**Mapbox's temporary geocoding** provides 100,000 free monthly requests at $0.75 per 1K thereafter, but prohibits caching results. Their permanent geocoding API requires enterprise licensing at significantly higher costs ($5 per 1K). Choose Mapbox primarily when their map visualization capabilities justify the geocoding costs.

**OpenCage charges $50 monthly** for 10,000 daily requests ($0.17 per 1K), with soft limits allowing temporary overages without surge pricing. Unlike restrictive providers, OpenCage permits permanent result storage even after canceling subscriptions. This permissive licensing makes OpenCage ideal for data warehousing and analytics applications.

**Geocodio specializes in North American addresses** (US and Canada only) with 2,500 free daily requests and $0.50 per 1K pay-as-you-go pricing. The remarkable value includes free data enrichment: Census data, political districts, Congressional districts, school districts, time zones, ZIP+4 codes, and Metropolitan Statistical Areas. Unlimited data storage and caching make Geocodio perfect for building analytics databases. Self-serve unlimited plans start at $1,000 monthly with 3,333 lookups per minute.

**SmartyStreets targets address verification** rather than pure geocoding, with USPS CASS-certified validation. The 250 free monthly lookups (US only) barely suffice for testing. Paid tiers start at $20 monthly for 500 lookups, scaling to typical enterprise contracts of $20,000-$50,000 annually (average $24,000). Building-level accuracy, apartment-level precision, and 55+ metadata points justify premium pricing for logistics applications where delivery accuracy is mission-critical.

## TypeScript support quality and developer experience

**Native TypeScript libraries deliver superior developer experience** compared to JavaScript libraries with community-maintained type definitions. @goparrot/geocoder, @googlemaps/google-maps-services-js, opencage-api-client, and universal-geocoder all provide types as authoritative documentation, eliminating version mismatch issues between library and @types packages.

**Google's TypeScript implementation sets the quality bar**. IntelliSense provides comprehensive autocomplete for all parameters with JSDoc documentation inline. The compiler catches common mistakes like invalid travel modes or missing required parameters. Response objects have full type inference—accessing `response.data.results[0].elevation` provides typed number values without assertions. Error handling gains type safety through Axios error types, with `error.response.data.error_message` properly typed. The library uses params/headers/body pattern consistently, creating predictable APIs across all Google Maps Platform services.

**@goparrot/geocoder leverages advanced TypeScript patterns**. The provider architecture uses generic types enabling type-safe configuration per provider. Location, Distance, and Suggestion classes strongly type domain objects. Enum support for TravelMode, Language, and other constants provides autocomplete of valid values. The dependency injection pattern (injecting Axios instances) enables sophisticated testing strategies. However, the reflect-metadata requirement adds complexity—you must import it once at application entry and ensure only one instance exists in node_modules.

**node-geocoder's TypeScript support reveals limitations** of JavaScript libraries with type definitions. The DefinitelyTyped types use declaration merging (function + namespace) that confuses developers expecting class-based patterns. The export is a function returning a Geocoder, not a class to instantiate. Error types lack strong typing, requiring manual type guards. Type definitions may lag library updates since community volunteers maintain them separately. Weekly downloads of @types/node-geocoder (20,000+) trail node-geocoder itself (70,000+), suggesting many users skip TypeScript support entirely.

**Bundle size considerations** matter for serverless and mobile applications. @aashari/nodejs-geocoding wins dramatically with zero dependencies, creating tiny bundles around 10KB. @googlemaps/google-maps-services-js requires Axios but produces moderate 50-100KB bundles. @goparrot/geocoder includes reflect-metadata and Axios, generating 100-200KB bundles. @mapbox/mapbox-sdk bundles reach 200-300KB for the full SDK. Modern bundlers with tree-shaking reduce these sizes by eliminating unused providers and services. For serverless functions, prefer lightweight options or use multi-provider libraries with individual provider imports.

**All modern libraries use async/await Promises**, eliminating callback hell. The older node-geocoder supports both callback and Promise syntax for backward compatibility. Universal-geocoder similarly maintains callback support for legacy code while recommending Promise patterns. Newer libraries like @goparrot/geocoder and @googlemaps/google-maps-services-js enforce async/await exclusively, creating cleaner codebases.

## Critical features for production deployments

**Batch processing accelerates bulk geocoding** when converting address databases or processing import files. node-geocoder provides built-in `batchGeocode()` methods accepting address arrays and returning promise arrays. This enables concurrent requests up to rate limits. Other libraries require manual implementation—typically using Promise.all() with rate limiting logic. For processing millions of addresses, consider services like Geocodio Unlimited or SmartyStreets that specialize in bulk operations.

**Rate limiting must be implemented at application level** since most libraries lack built-in rate limiting. OpenStreetMap/Nominatim strictly enforces 1 req/sec, requiring queuing logic. LocationIQ limits free tier to 2 req/sec, paid plans to 20 req/sec. Google allows 3,000 queries per minute (50 per second). Implement rate limiting using libraries like Bottleneck or p-queue, or build custom token bucket algorithms. The opencage-api-client tutorial demonstrates rate-limiting patterns worth studying.

**Caching dramatically reduces costs and improves performance**. Check provider terms before implementing—Google prohibits caching beyond 30 days, while OpenCage and Geocodio permit permanent storage. Simple in-memory caching using Map objects works for small datasets. Redis provides distributed caching for multi-server deployments. Consider geocoding result stability: addresses rarely change coordinates, making aggressive caching safe. Implement cache keys based on normalized addresses (lowercase, standardized formatting) to improve hit rates.

**Error handling requires special attention** in multi-provider architectures. Providers return different HTTP status codes and error formats. Implement retry logic with exponential backoff for transient failures (rate limits, timeouts). Use circuit breaker patterns to stop hammering failing providers. Log provider response times to detect degraded performance. ChainProvider patterns in @goparrot/geocoder and universal-geocoder automatically failover to backup providers, increasing resilience.

**Accuracy varies by provider and region**. Google Maps generally provides best global accuracy through extensive manual curation and user feedback. OpenStreetMap quality depends on local mapping community activity—excellent in urban areas and well-mapped regions, variable in rural areas. Geocodio excels for US addresses with TIGER/Line data integration. HERE shows strength in European data. Consider running parallel provider queries for critical applications, comparing results and flagging discrepancies for manual review.

## Data licensing restrictions and compliance

**Provider terms of service impose critical constraints** that dramatically affect architecture decisions. Google and Bing require displaying geocoding results on their respective maps and prohibit long-term storage (30-day maximum caching). These restrictions eliminate Google for analytics applications building permanent address databases. Azure Maps follows similar restrictions. TomTom permits display on third-party maps but prohibits data storage beyond temporary caching.

**Permissive providers** enable unrestricted data usage. Geocodio, OpenCage, and LocationIQ explicitly allow permanent result storage with no restrictions on map display. You can geocode addresses once, store coordinates permanently, and display results on any mapping platform (Mapbox, Leaflet, Google Maps). This flexibility matters enormously for data warehousing, offline applications, and multi-platform deployments. Read provider terms carefully—they change frequently.

**OpenStreetMap's ODbL license** requires attribution and share-alike for derivative databases. Most Nominatim usage complies easily with attribution links. However, creating proprietary databases from OSM data requires legal review. Commercial OSM-based providers like LocationIQ handle licensing complexity, letting you use permissive terms while they manage OSM compliance.

## Recommendations by use case

**For new TypeScript projects requiring multi-provider flexibility**, choose @goparrot/geocoder. The native TypeScript implementation, provider abstraction layer, and modern architecture justify the moderate learning curve. Implement ChainProvider with OpenStreetMap/Nominatim as primary (free) and LocationIQ as fallback (generous free tier). This combination handles most geocoding needs free while providing paid backup for rate limit spikes.

**For Google Maps-only applications**, use @googlemaps/google-maps-services-js exclusively. The official support, superior TypeScript integration, and comprehensive Google Maps Platform coverage (places, directions, distance matrix) justify vendor lock-in. Budget approximately $5 per 1,000 requests after the $200 monthly credit, and ensure you can comply with display-on-Google-maps requirements.

**For North American address validation and analytics**, Geocodio delivers exceptional value. The permissive data storage terms, included Census enrichment, and affordable pricing ($0.50 per 1K) make this ideal for building address databases. Use the official Node.js SDK with full TypeScript support. Consider the Unlimited plan ($1,000/month) for processing millions of addresses monthly with 3,333 lookups per minute rate limits.

**For global applications on tight budgets**, combine node-geocoder with LocationIQ. Despite inactive maintenance, node-geocoder's stability and multi-provider support remain unmatched. LocationIQ's 60,000 free monthly requests and aggressive paid pricing ($0.017 per 1K at volume) support rapid growth. Implement caching to maximize the free tier—LocationIQ permits permanent storage on paid plans.

**For logistics and delivery applications**, invest in SmartyStreets address verification. Building-level accuracy, apartment-level precision, and USPS CASS certification reduce failed deliveries more than the $20,000-$50,000 annual costs. The 55+ metadata points (delivery point validation, residential indicator, vacancy status) integrate with routing systems. Pair SmartyStreets validation with HERE or Google geocoding for international addresses.

**For applications requiring beautiful custom maps**, choose Mapbox despite expensive permanent geocoding. The cohesive platform (geocoding, maps, navigation) creates superior user experiences. Budget carefully—temporary geocoding at $0.75 per 1K works for simple lookups, but permanent geocoding requires enterprise licensing. The mobile SDKs (iOS, Android, Unity) excel for location-based mobile applications.

**For startups and MVPs**, maximize free tiers through intelligent provider selection. HERE's 250,000 monthly requests handle substantial traffic free. Implement lazy geocoding—only geocode addresses when users explicitly need map display, not on every record create. Use LocationIQ's startup program (50% off for 12 months) once you exceed free tiers. Monitor usage carefully to avoid surprise bills when crossing tier boundaries.

## Conclusion

The geocoding library landscape offers mature TypeScript options beyond the dominant but unmaintained node-geocoder. **Choose @goparrot/geocoder for new TypeScript projects needing multi-provider flexibility**, @googlemaps/google-maps-services-js for Google-only integrations, or opencage-api-client for OpenCage devotees. Free options combining OpenStreetMap/Nominatim or LocationIQ with proper rate limiting handle most applications successfully.

**Data licensing restrictions matter more than pricing** for many applications. Google's 30-day caching limit and display requirements eliminate it for analytics use cases, regardless of the $200 monthly credit. Geocodio and OpenCage permit permanent storage, enabling data warehousing and offline applications. Always read provider terms before architecture decisions—switching providers later requires re-geocoding entire databases.

For production deployments, implement rate limiting, caching, error handling with retries, and provider failover strategies regardless of library choice. Monitor provider response times and accuracy to detect degraded service. Budget for paid tiers once exceeding free limits—the cost of failed deliveries or poor user experience exceeds geocoding expenses.
