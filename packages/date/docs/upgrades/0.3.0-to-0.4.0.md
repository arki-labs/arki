# Parsers return, builders throw

`parseISO`, `parseDate`, `parseDateTime`, `parseZoned` and `fromPickerDate` take outside input. They now return the value or an `@arki/failure` value. They no longer throw on bad input. Narrow the result before you use it.

```ts run
import { InvalidDateText, parseDate } from '@arki/date';
import { isFailure } from '@arki/failure';

const result = parseDate('2026-02-30', 'yyyy-MM-dd');
if (isFailure(result)) {
  if (!InvalidDateText.is(result) || result.data.reason !== 'invalid_date') throw new Error('Unexpected failure');
} else {
  result.add({ days: 1 });
}
```

The failures, exported from the root entry:

- `InvalidDateText` (`date.invalid_text`, 400). `data` is `{ operation, reason, input, truncated }`. `reason` is one of `DATE_TEXT_REASONS`. `input` is the text cut to 64 characters.
- `InvalidNativeDate` (`date.invalid_native_date`, 400). `fromPickerDate` got an Invalid Date.
- `UnknownTimeZone` (`date.unknown_time_zone`, 400). `parseZoned`, `parseISO` (`options.timeZone`) or `fromPickerDate` (`basis: 'zone'`) got a zone name the runtime does not know. `data.timeZone` is the name cut to 64 characters.

## Removed

`tryParse`, `tryParseDate`, `tryParseDateTime`, `tryParseZoned` and the `ParseKinds` and `ParseResult` types are gone. There is no compatibility re-export.

- `tryParseDate(text, pattern)` becomes `parseDate(text, pattern)` and a failure check instead of an `undefined` check. The same goes for `tryParseDateTime` and `tryParseZoned`.
- `tryParse(text, 'iso')` becomes `parseISO(text)`.
- `tryParse(text, 'plainDate' | 'plainDateTime' | 'instant' | 'zoned')` has no direct replacement. Read the text with `parseDate`, `parseDateTime`, `parseZoned` or `parseISO`. Or, for text in your own code, call the builder and let it throw.

## Unchanged

The builders `plainDate`, `plainDateTime`, `instant`, `zoned`, `fromUnix`, `fromMillis` and `inZone` still throw `RangeError` on a bad value. They are for your own values. A zone name passed to them is your own value too: check outside names with `isValidTimeZone` first. A bad pattern given to a `parse*` function is a bug and still throws.

`fromUnix` now throws its own `RangeError` for seconds past ±8.64e12. Before, a huge finite value overflowed to `Infinity` and `BigInt` threw a bare error.
