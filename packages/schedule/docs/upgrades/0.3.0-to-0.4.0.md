# Upgrade @arki/schedule 0.3.0 to 0.4.0

Act if you call `schedules(needs, defs)` with a needs object in a Dot feature. Skip it if you only use `schedules([defineSchedule(...)])` or `schedules(core, defs)`.

## What changed

Breaking:

- The `schedules(needs, defs)` overload is removed. It belonged to the object-form feature API, which `@arki/dot` 0.8.0 deletes. Use `schedules(core, defs)` in the feature's `.entrypoints(...)`. The handler gets what the feature's entrypoints get: its needs, its private infra and `usecases`. A missing need is a compile error.

## Steps

1. Replace each `schedules(needs, defs)` call. Pass the feature core instead of the needs object.

   ```ts skip="removed in 0.4.0"
   // before
   const billing = feature('billing', {
     needs: { db: database.provides.db },
     use: [
       schedules({ db: database.provides.db }, [
         { name: 'send-digest', cron: '*/15 * * * *', handler: ({ db }) => sendDue(db) },
       ]),
     ],
   });
   ```

   ```ts skip="needs a Dot app"
   // after
   import { defineFeature } from '@arki/dot/feature';
   import { schedules } from '@arki/schedule/dot';

   const billingLogic = defineFeature('billing')
     .needs({ db: database.provides.db })
     .usecases({ sendDue });

   export const billing = billingLogic.entrypoints(
     schedules(billingLogic, [
       { name: 'send-digest', cron: '*/15 * * * *', handler: ({ usecases }) => usecases.sendDue() },
     ]),
   );
   ```

2. Move the feature to the chain API first if it still uses `feature('x', { ... })`. See `packages/dot/docs/upgrades/0.7.0-to-0.8.0.md`.

`schedules([defineSchedule(...)])` and `schedule({ ... })` are unchanged.
