# 0.1.3 to 0.2.0

`Flow.run` now returns an `UnexpectedDefect` when its retry wait fails. This is the original canonical value returned by `@arki/async`; the flow makes no further attempt and emits no completion event. Check the result with `isFailure` before reading successful state. Existing node refusals keep their inferred definitions and identity.

A retry-wait defect is final. Propagate it through an owning operation rather than turning it into a retry or a fallback success. App adapters that persist a failed business state must perform that transition before returning the failure. A CLI or another real foreign exception boundary may bridge it explicitly with `orThrow`.

This change migrates the retry-wait outcome. Existing FlowError exception paths retain their documented behaviour; it does not claim a complete migration of every AI execution boundary.
