# Retry cancellation

Retry refuses a pre-aborted signal before invoking the callback or clock. If the callback rejects after cancellation, or a backoff predicate or observer cancels before more work, retry returns `Cancelled` (`resilience.cancelled`) with the signal reason kept as a private cause. `onThrow` and `withFallback` never recover cancellation. Completed success values and canonical refusals are preserved by identity; cancellation does not erase an answer already produced.

Use `RetryFailure` and `RETRY_FAILURES` for retry-capable policies, including RPC error declarations. They infer the exact union from `Cancelled` and the existing clock definitions. `RetryWaitFailure` and `RETRY_WAIT_FAILURES` remain the narrower wait-only contract. Actual clock cancellation still returns its original `SleepCancelled`; the retry loop does not relabel it.

```ts run
import { isFailure } from '@arki/failure';
import { Cancelled, createRetryPolicy } from '@arki/resilience';

const controller = new AbortController();
controller.abort();
const outcome = await createRetryPolicy().execute(() => 'done', controller.signal);
if (!isFailure(outcome) || !Cancelled.is(outcome)) throw new Error('Expected cancellation');
```

This is cooperative cancellation, not a new deadline. A callback that never settles must observe its signal or run under an explicit timeout. Engine-only circuit/timeout/bulkhead policies retain their existing thrown bridge; other public defect supervision remains pending. No new telemetry span is added by this cancellation check.

## Observation cannot change execution

All owned policy event subscriptions now supervise listener throws and rejected promises. A success observer can no longer trigger a retry or fallback; a timeout observer cannot block timeout settlement; breaker and bulkhead observers cannot replace the original outcome. Pending listener promises are not awaited. Synchronous listener cancellation of an owned signal still works.

Move required writes and control decisions from listeners into the operation callback or the explicit backoff predicate. Do not throw from an event listener to cancel work. The original event remains available to custom listeners, but `attachPolicyLogger` and the Dot adapter now put a canonical code in the `error` diagnostic field instead of a private error message or stringified payload. Unknown throws use `failure.unexpected_defect`. Observer defects report that code through `arki:resilience`; diagnostic reporter errors are isolated too.

No public failure union changes in this observation slice. Existing engine throw bridges and public callback-defect normalization are still pending migration.

Observer-defect diagnostics are coalesced while a diagnostic reporter is pending. Reporting resumes after settlement; operation execution never waits for that reporter.
