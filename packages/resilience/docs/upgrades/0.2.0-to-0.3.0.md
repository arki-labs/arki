# Retry cancellation

Retry refuses a pre-aborted signal before invoking the callback or clock. If the callback rejects after cancellation, or a backoff predicate or observer cancels before more work, retry returns `Cancelled` (`resilience.cancelled`) with the signal reason kept as a private cause. `onThrow` and `withFallback` never recover cancellation. Completed success values and canonical refusals are preserved by identity; cancellation does not erase an answer already produced.

Use `RetryFailure` and `RETRY_FAILURES` for retry-capable policies, including RPC error declarations. They infer the exact union from `Cancelled` and the existing clock definitions. `RetryWaitFailure` and `RETRY_WAIT_FAILURES` remain the narrower wait-only contract. Actual clock cancellation still returns its original `SleepCancelled`; the retry loop does not relabel it.

```ts run
import { isFailure } from '@arki/failure';
import { Cancelled, createRetryPolicy } from '@arki/resilience';

const controller = new AbortController();
controller.abort();
const outcome = await createRetryPolicy().execute(() => 'done', controller.signal);
if (!isFailure(outcome) || !Cancelled.is(outcome)) throw new Error('Expected cancellation');
```

This is cooperative cancellation, not a new deadline. A callback that never settles must observe its signal or run under an explicit timeout. All engine policies now return owned failures; see the engine-outcome migration below. No new telemetry span is added by this cancellation check.

## Observation cannot change execution

All owned policy event subscriptions now supervise listener throws and rejected promises. A success observer can no longer trigger a retry or fallback; a timeout observer cannot block timeout settlement; breaker and bulkhead observers cannot replace the original outcome. Pending listener promises are not awaited. Synchronous listener cancellation of an owned signal still works.

Move required writes and control decisions from listeners into the operation callback or the explicit backoff predicate. Do not throw from an event listener to cancel work. The original event remains available to custom listeners, but `attachPolicyLogger` and the Dot adapter now put a canonical code in the `error` diagnostic field instead of a private error message or stringified payload. Unknown throws use `failure.unexpected_defect`. Observer defects report that code through `arki:resilience`; diagnostic reporter errors are isolated too.

Observation supervision itself adds no failure union. The engine-outcome migration below owns public operation changes.

Observer-defect diagnostics are coalesced while a diagnostic reporter is pending. Reporting resumes after settlement; operation execution never waits for that reporter.

## Engine outcomes and raw fallback

Remove `CircuitOpenError`, `TimeoutError`, `CancelledError`, `BulkheadRejectedError`, `RetriesExhaustedError`, `isResilienceError`, `isBrokenCircuitError` and `isBulkheadRejectedError`. Their expected-outcome codes E001–E005 are removed. Use canonical `CircuitOpen`, `Timeout`, `Cancelled`, `BulkheadRejected` and `.is(result)`. Retry exhaustion preserves the last returned failure, or returns `UnexpectedDefect` with the original thrown cause kept private. Static `InvalidBackoffError`/E006 and its `ResilienceError` base remain.

Every `PolicyExecution` admits `EXECUTION_FAILURES`. Use each policy's original failure tuple, or `RESILIENCE_FAILURES` for presets/composed policies in RPC admission. Heterogeneous `wrap` keeps the union of its actual inputs. `withFallback` also accepts execution-only policies, retaining exact fallback and failure types.

Default callback throws still retry. `onThrow` and `withFallback` see the raw original error after retry; unknown final throws, including a throwing mapper, become `UnexpectedDefect`. Returned engine refusals bypass throw fallback and retry by default. Replace fallback-on-open-error logic with `CircuitOpen.is(result) ? cached : result`. Explicit `.while(Timeout)` can retry a deadline, but timed-out work can still be running: pass its signal and reconcile effects first.

Timeout versus caller cancellation is captured before observers can alter signals. Pre-aborted calls do no work. Private SDK-shaped callback throws never masquerade as engine refusals. Observer supervision and exact returned failure identity remain.

HTTP keeps final retryable responses and maps raw network errors through an explicit throw fallback; engine circuit/capacity refusals remain canonical client failures. DB uses raw final SQLSTATE mapping before defect normalization so exhausted conflicts retain attempts/state and uncertain commits stay non-retryable. Embeddings admits `UnexpectedDefect`, preserving clock defects instead of asserting that every non-provider failure is cancellation.
