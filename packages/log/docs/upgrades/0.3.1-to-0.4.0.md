# Upgrade @arki/log 0.3.1 to 0.4.0

Act on this only if your code catches the error that `file()` throws when it cannot open its path, or relied on a `.to(name)` logger throwing for an undefined channel. Everyone else can upgrade without changes.

## What changed

- Fix the foundation findings of the T08 review.
  
  - `@arki/log`: `maskSecrets` and `otelSink` handle an object that contains itself (the cycle becomes `[Circular]`) instead of dropping the record. A `.to('name')` logger whose channel is not defined no longer throws into the caller at log time; the fault is reported once and the channel is skipped. `file()` throws a coded `LogError` (`ARKI_LOG_E006`) when it cannot open its path.
  - `@arki/async`: `debounce` and `throttle` take an `onError` option. An error thrown by the callback, or a promise it returns that rejects, goes there. Without it the error is rethrown from a microtask. The schedule stays consistent and a leading call never throws into the caller.
  - `@arki/env`: `rotateEnvFiles` returns an `InvalidInput` failure for an empty list or files of two environments (it threw a plain `Error`). The default `onValidationError` of `defineEnv` throws an `UnexpectedFailure` that carries the new `env.invalid_environment` failure (`InvalidEnvironment`).

## Steps

1. Upgrade the package:

   ```sh
   bun add @arki/log@^0.4.0
   ```

2. If you catch the error from `file()` at configure time, match the code instead of the raw file-system error:

   ```ts
   import { configure, LogError, LOG_ERROR_CODES } from '@arki/log';
   import { file } from '@arki/log/node';

   // before: the raw fs error (for example ENOENT) reached you
   // after
   try {
     configure({ channels: { file: file({ path: '/var/log/app.log' }) }, default: { level: 'info', channels: ['file'] } });
   } catch (error) {
     if (error instanceof LogError && error.code === LOG_ERROR_CODES.fileOpenFailed) {
       // error.cause is the original file-system error
     }
     throw error;
   }
   ```

3. If you relied on `.to('name')` throwing when `name` is not a defined channel, check your channel list instead: the logger now reports the fault once and skips that channel, so logging never throws into your code.

## Verify

```sh
bun run typecheck && bun run test
```

Both pass. A misconfigured channel now shows up as one reported fault instead of an exception.
