# Upgrade @arki/kv 0.5.0 to 0.6.0

You must act only if you use `redisResponseCache` and have dashboards or alerts that count `kv.*` spans; everyone else can skip it.

## What changed

- `redisResponseCache` (`@arki/kv/redis/idempotency`) now spans each call: `kv.idempotency.begin`,
  `kv.idempotency.finish` and `kv.idempotency.abandon`, counted in `kv.commands`. Every `kv.*` span now sets the
  `failure.code` attribute when a command returns a failure, like the other `@arki/*` packages (an attribute change,
  so minor). A broken OpenTelemetry SDK can no longer make a KV command throw: telemetry errors are swallowed. Keys,
  values, owners and responses are never recorded.
  
  no docs impact: README gains an Observability section; no API changed.
  no demo impact: no demo reads kv telemetry.

## Public API changes

No public API changes.

## Steps

1. Add the new idempotency spans to any dashboard that lists `kv.*` spans: `kv.idempotency.begin`, `kv.idempotency.finish` and `kv.idempotency.abandon`. They are also counted in `kv.commands`.

   Before:

   ```text
   sum(kv.commands) by command   # no idempotency commands
   ```

   After:

   ```text
   sum(kv.commands) by command   # includes kv.idempotency.begin, finish and abandon
   ```

2. Read the `failure.code` attribute on any `kv.*` span to find commands that returned a failure. No code change is needed.

## Verify

Run the package tests. They pass when the new spans and attribute work.

```sh
bun run test
```
