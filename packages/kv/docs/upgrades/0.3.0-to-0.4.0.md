# Upgrade @arki/kv 0.3.0 to 0.4.0

Act on this if you connect to a `rediss://` server with a self-signed certificate, import `kv` from `@arki/kv/instance`, call `KV.close()` yourself, or catch the error `createKV` throws. Apps that only use the `kv()` Dot plugin against a server with a valid certificate can skip the steps.

## What changed

- Breaking changes, found by the T08 review.
  
  - TLS certificates are now verified for `rediss://` URLs. Before, every `rediss://` URL skipped the check. For a self-signed server you trust, pass `{ allowUnverifiedTls: true }` as the fourth argument of `new KV`, set `KV_ALLOW_UNVERIFIED_TLS=true`, or use the `allowUnverifiedTls` Dot option.
  - `KV.close()` now returns a `kv.close_failed` failure (`KvCloseFailed`) when a disconnect fails, instead of printing to the console and resolving. The Dot plugin throws it on dispose.
  - `@arki/kv/instance` no longer exports `kv`, which built a client when the module loaded. Call `createKVInstance()` once in your app.
  - `createKV` and `createRateLimitKV` throw `KVInitializationError` (`KV_INIT_E004`) when no URL is set, instead of a plain `Error`.
  - `setIfNotExists` now writes the same key and format as `set`, so `get` reads its value back. `mset` now applies its expiry to every pair.
  - The rate limiter fallback to memory is no longer silent: it logs a warning and lists the id in `KV.degradedRateLimiters`. A memory limiter is replaced by a Redis one on the next `getRateLimiter` call after Redis is ready. Before, the memory limiter stayed cached for good.
  - `setIfNotExists` and `publish` wait for the Redis connection instead of failing with a raw "Stream isn't writeable" error right after the client is made.
  - Every command runs in a `kv.<command>` span and counts in the `kv.commands` metric (new dependency `@opentelemetry/api`). Console output is replaced by `@arki/log`.
  
  No docs impact beyond the README and agent guide, updated here. No demo impact.

## Public API changes

Removed:

- `kv` from `@arki/kv/instance` (a client built when the module loaded).

Changed:

- `KV.close()` resolves to `KvCloseFailed | undefined` instead of `void`.
- `createKV` and `createRateLimitKV` throw `KVInitializationError` (code `KV_INIT_E004`) instead of a plain `Error` when no URL is set.
- `rediss://` URLs verify the server certificate.

Added:

- `KvOptions` with `allowUnverifiedTls`, the fourth argument of `new KV`; the `KV_ALLOW_UNVERIFIED_TLS` env var; the `allowUnverifiedTls` option of the `kv()` Dot plugin.
- `KvCloseFailed` (failure code `kv.close_failed`), exported from `@arki/kv` and `@arki/kv/errors`.
- `KV.degradedRateLimiters`: the ids of rate limiters running in memory because Redis was not ready.
- The `kv.<command>` spans and the `kv.commands` metric.

## Steps

1. If your Redis uses a self-signed certificate you trust, allow it. Without this, the connection now fails TLS verification.

   ```sh
   # before: rediss:// skipped the certificate check
   # after: opt in for a server you trust
   KV_ALLOW_UNVERIFIED_TLS=true
   ```

   Or in code, as the fourth argument: `new KV(url, 'pizzeria', 'rl', { allowUnverifiedTls: true })`.

2. Replace the `kv` import from `@arki/kv/instance` with one `createKVInstance()` call in your app.

   ```ts skip="before: the 0.3.0 API"
   import { kv } from '@arki/kv/instance';
   ```

   ```ts skip="needs KV_URL at runtime"
   import { createKVInstance } from '@arki/kv/instance';

   export const kv = createKVInstance('pizzeria');
   ```

3. If you call `KV.close()` yourself, check its result. It used to log and resolve.

   ```ts skip="needs a running Redis"
   import { isFailure } from '@arki/failure';

   const failed = await kv.close();
   // `failed.code` is 'kv.close_failed'; the connection may still be open, so report it.
   if (isFailure(failed)) throw failed;
   ```

4. If you catch the error from `createKV` or `createRateLimitKV`, match on `KVInitializationError` and `error.code === 'KV_INIT_E004'` instead of the message text.
