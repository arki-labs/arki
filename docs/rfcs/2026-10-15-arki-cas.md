## 1. Problem

`@arki/expr` replaced mathjs in 13 of Ekuation's 15 files. Two remain, because they need algebra, not evaluation:

- **DE** `derivative-calculator/state.ts` calls `derivative` 3 times and `simplify` 3 times (lines 348, 351, 376, 538, 541, 570).
- **EQ** `equation-solver/state.ts` calls `rationalize(…, {}, true)` once (line 784) and `derivative` once (line 301).

(Fable's review counts 17/9/6 uses; most are in research docs such as `equation-solver/docs/claude.md`. The source has 4 `derivative`, 3 `simplify`, 1 `rationalize`.)

Keeping mathjs for these 8 calls costs the whole library in those routes, plus the two migration tests that import it. The probe also shows real defects in what users see:

| d/dx `log(x, 2)` | `1.4426950408889634 / x` | Same. |

## 2. Goals and non-goals

**Goals**
1. Symbolic `derivative` of any order over the expr function set, with an optional step trace (§9).
2. `expand`, `collect`, `rationalize` and polynomial extraction over ℚ, exactly. `gcd` and `factor` of polynomials over ℚ (§8).
3. A small, documented `simplify`: a fixed rule table, each rule with its stated condition (§7).
4. Truthful results. Every rewrite keeps the domain conditions it needs. Results list the conditions they rely on. What cas cannot do stays unevaluated or throws a typed error. It never guesses (§6).
5. Input and output are the expr AST, so results print, render as LaTeX and compile with expr (§5).
6. Bounded: every operation has budgets checked before the work, and cancellation (§10).
7. Zero runtime dependencies beyond `@arki/expr` and `@arki/math`. Runs on Node, Bun, Deno, browsers and Hermes (§16).
8. A general-purpose library: designed for public use, with Ekuation as the first acceptance test.

**Non-goals** (synthesis "Never" list)
- Symbolic integration (Risch or heuristic), symbolic limits, series, general equation solving.
- SymPy or Mathematica parity. Trig-identity heuristics (`sin^2 + cos^2 → 1`), log expansion, radical denesting.
- A complex domain. v1 is real-only (§6).
- User-defined rewrite rules (mathjs accepts rule strings: a second parser surface).
- A "try everything, keep the shortest" simplifier. Output form is a normal form, not a search result.

## 4. Design overview

```
expr AST ──read──▶ term DAG (hash-consed, kernels) ──▶ normal forms (Poly / RatFun over ℚ)
                                                         │   rules with conditions
expr AST ◀──parse(print)── canonical tree ◀──────────────┘   + conditions + optional steps
```

All work happens on an internal representation. The public API takes and returns expr values only.

## 5. Representation

**Input.** An `Expr` (`version: 1`) or a string, which is parsed with expr's canonical `scientific` syntax. Locale input is the caller's job: parse with `syntaxFor(locale)` first, then pass the `Expr`.
- `group` nodes are transparent. `implicit` is ignored (it only affects printing).
- Number literals are read from `raw` with expr's Rational reader, so `0.01` is exactly `1/100` and `1e-7` is `1/10^7`.
- Names resolve through `names(expr, { language })`: variables, the constants `pi` and `e` (kept symbolic, never floated), and functions. `i` is rejected in v1 (`CasError` `not-in-domain`, with its span).
- Host functions from a custom `Language` are opaque: `simplify` treats `f(u)` as a kernel; `derivative` throws `unsupported-function` if `u` contains the variable, and returns `0` if it does not.
- cas accepts AST `version: 1` only. cas and expr are both 0.x and move in lockstep; there is no shim.

**Internal forms.**
- **Term DAG.** Nodes are hash-consed per call: equal subterms are one object. The DAG is built for one call and dropped afterwards; it is never a cache across calls.
- **Kernels.** Anything that is not `+ - * / ^integer` over names and rationals: `sin(u)`, `exp(u)`, `ln(u)`, `u^(p/q)`, `abs(u)`, opaque host calls. Kernels are keyed by their canonical print, and `exp(u)` and `e^u` are the same kernel. Their arguments are normalized recursively.
- **`Poly`.** A sparse multivariate polynomial over `Rational`: a map from monomial (sorted exponent vector over names and kernels) to a non-zero coefficient. Univariate dense arrays are used inside `gcd` and `factor`.
- **`RatFun`.** A numerator and denominator `Poly`, with a gcd-cancelled, sign-normalized denominator (positive leading coefficient, integer content). Every cancelled factor becomes a condition (§6).

**Output.** cas builds a canonical tree, prints it with expr's `print`, and parses that text again. So a result is a normal `Expr`: `source` is canonical text, spans point into it, `parse(print(r))` holds by construction, and `toLatex` works unchanged. cas emits no `group` nodes; expr's printer adds parentheses where the tree needs them. The re-parse costs one parse per result. It buys one code path for spans and a round-trip guarantee.

**Canonical form** (proposal; Q2 decides).
- Sums: by descending degree in the main variable (the differentiation or `collect` variable, else the first name in source order), then kernels in a fixed order, constant last: `3*x^2 - 4*x + 1`.
- Products: the rational coefficient first, then names, then kernels: `2*y*x` becomes `2*x*y` when `x` is the main variable.
- Rational functions: one fraction. The numerator is expanded. The denominator is kept as a product of the factors it was built from: `(x^2 - 2*x - 1)/(x - 1)^2`.
- A common non-polynomial factor of all terms is pulled out: `exp(x)*(cos(x) - sin(x))`, not `exp(x)*cos(x) - exp(x)*sin(x)`.
- Negative terms print as subtraction. Rationals print as fractions, `x/50` (Q3: optional decimal output `0.02*x` for terminating values).

## 6. Assumptions and conditions

v1 is **real-only**: every variable ranges over ℝ, and every function means its real version.

**The contract.** Let D be the input's natural domain: every denominator ≠ 0, `ln`/`log` argument > 0, `log(x, b)` with b > 0 and b ≠ 1, `sqrt` and even-root arguments ≥ 0, `asin`/`acos` with 1 − u² ≥ 0, `tan`/`sec` with `cos(u)` ≠ 0, and so on. Then:

1. Wherever the input is defined and the caller's assumptions hold, the result is defined and has the same value.
2. A rewrite may **widen** the domain (remove a point where the input was undefined). Every such lost restriction is returned in `conditions`.
3. A rewrite may **never narrow** it (change the value somewhere the input is defined) unless the caller's assumptions prove the rewrite safe. Without proof the rewrite is not applied and the term stays as it is.

```ts
type Relation = 'nonzero' | 'positive' | 'nonnegative';
type Condition = {
  readonly subject: Expr;               // canonical, e.g. `x - 1`
  readonly relation: Relation;
  readonly reason: 'domain' | 'differentiable';
};
```

**The required examples.**

| Rewrite | When applied | Result carries |
| --- | --- | --- |
| `x/x → 1` | always | `x ≠ 0` (lost restriction) |
| `(x^2 - 1)/(x - 1) → x + 1` | always | `x - 1 ≠ 0` |
| `sqrt(x^2) → abs(x)` | always (real x) | nothing |
| `sqrt(x^2) → x` | only if `x ≥ 0` is proven | nothing |
| `sqrt(x)^2 → x` | always | `x ≥ 0` |
| `exp(ln(x)) → x` | always | `x > 0` |
| `ln(exp(x)) → x` | always | nothing: over ℝ this holds for every x. (Over ℂ it fails outside the principal strip; that is why the domain is explicit.) |
| `(x^a)^b → x^(a*b)`, non-integer `b` | only if `x > 0` is proven | nothing |
| `0 * ln(x) → 0` | always | `x > 0` |

**Supplying assumptions** (Q4): per call, per variable.

```ts
type Assumption = 'nonzero' | 'positive' | 'nonnegative' | 'negative';
type Assumptions = Readonly<Record<string, Assumption>>;
```

**The sign oracle** decides "proven". It is small, sound and incomplete, and documented as a table: assumed signs of names; positive rational constants; `pi`, `e`, `exp(u)` > 0; `u^2k` ≥ 0; `abs(u)` ≥ 0; sums of non-negatives with one positive term > 0 (`x^2 + 1`); products and quotients by sign rules. When it cannot decide, the answer is "unknown", and unknown never licenses a rewrite.

**Pruning.** A condition is dropped when it is already visible in the result (the same subject is still a denominator, a `ln` argument, and so on) or when the assumptions or the sign oracle prove it. Matching is exact on canonical subjects, and `positive` implies `nonzero` and `nonnegative`. Conditions are deduplicated.

**Derivatives** carry two kinds: lost domain restrictions (d/dx `ln(x)` = `1/x` with `x > 0`, reason `domain`) and points where the input is not differentiable (d/dx `abs(x)` with `x ≠ 0`, reason `differentiable`).

`conditionToLatex(c)` in the core prints `x \neq 0`, `x > 0`, `x \geq 0`. It is math notation, not English, so apps need no translation for it.

## 7. `simplify`: the rule table

`simplify` = build `RatFun` normal form (rules 1–4) + the kernel rules below, applied bottom-up to a fixed point. Each rule only shrinks or reorders the term under a well-founded order, so the fixed point exists; the fuel budget (§10) is a backstop, not the termination argument.

| Id | Rewrite | Condition needed | Recorded |
| --- | --- | --- | --- |
| `fold` | exact ℚ arithmetic on literals; `0*u → 0`; `u + 0`, `1*u`, `u^1`, `u/1` | — | lost restrictions of dropped `u` |
| `collect` | like terms and like powers (`x + x → 2*x`, `x*x → x^2`) | — | — |
| `cancel` | gcd cancellation in a fraction | — | cancelled factor ≠ 0 |
| `integer-powers` | `u^a * u^b → u^(a+b)`, `(u^a)^b → u^(a*b)` for integers | — | `u ≠ 0` when a negative exponent disappears |
| `fractional-powers` | the same for non-integer exponents | `u > 0` proven | — |
| `sqrt-of-square` | `sqrt(u^2) → abs(u)`; `→ u` | `u ≥ 0` proven for `→ u` | — |
| `square-of-sqrt` | `sqrt(u)^2 → u`, likewise `nthRoot` | — | `u ≥ 0` |
| `exp-ln` | `exp(ln(u)) → u` | — | `u > 0` |
| `ln-exp` | `ln(exp(u)) → u` | real (v1 always) | — |
| `exp-product` | `exp(a) * exp(b) → exp(a + b)`, `exp(a)^n → exp(n*a)` | — | — |
| `abs-sign` | `abs(u) → u` or `-u`; `abs(u)/u → sign(u)` | sign of `u` proven for the first; — for the second | `u ≠ 0` for the second |
| `parity` | `sin(-u) → -sin(u)`, `cos(-u) → cos(u)`, and the other odd and even functions | — | — |
| `special-values` | `sin(0)`, `cos(0)`, `tan(0)`, `exp(0)`, `ln(1)`, `ln(e)`, `sqrt` and `abs` of rationals with exact results (`sqrt(4/9) → 2/3`) | — | — |

`simplify` returns the ids it applied, so an app can show them. Anything not in this table is left alone. The table is the documentation; adding a rule is a minor release with a changelog entry and its own property tests.

## 8. Polynomial operations

- **`expand(e)`**: products and integer powers of sums, by the multinomial theorem. Kernels stay as atoms.
- **`collect(e, x)`**: group by powers of `x`; coefficients may contain other names and kernels.
- **`rationalize(e)`**: one fraction `numerator/denominator` with polynomial parts, cancelled by gcd, with conditions.
- **`polynomialIn(e, x)`**: the EQ entry point. It answers a question, so it returns a union instead of throwing:
  - `polynomial`: ascending exact coefficients (`[]` for the zero polynomial), plus conditions (`x/x - 1` → `[]` with `x ≠ 0`).
  - `rational`: numerator and denominator coefficients after cancellation; the roots of the denominator are excluded.
  - `other`: with reason `transcendental` or `symbolic-coefficient`, and the span of the first offending input node.
- **`gcd(a, b)`**: univariate over ℚ by primitive subresultant PRS over ℤ after clearing denominators, result monic. Multivariate is recursive: one main variable, coefficients in ℚ[other names]. A modular (Brown) gcd is added later only if benchmarks show the need.
- **`factor(e, x)`** (Q7): content, square-free factorization (Yun), then linear factors from the rational root test. The result says `complete: false` when an unfactored part of degree ≥ 4 remains (degree 2 and 3 parts without rational roots are irreducible over ℚ, so those are complete).

## 9. `derivative` and steps

- Rules: constant, variable, sum, constant multiple, product, quotient, power (constant exponent), exponential (constant base), general power `u^v` via `exp(v*ln(u))`, logarithm, the trig, inverse trig, hyperbolic and inverse hyperbolic families, roots, `abs`. All by the chain rule on the DAG, with one derivative per shared subterm (memoized per call). So the cost is linear in the DAG, and one product rule cannot double the work.
- The **rule-applied form** (S-05) is the rules' direct output with only `fold` applied (`3*x^2 - 2*2*x + 1`, not mathjs's `3 * 1 * x ^ (3 - 1) - …`). The simplified form is `simplify` of it.
- Higher orders normalize between orders (as DE does today, DE 539).
- `floor ceil round fix sign mod max min`, `factorial` and `gamma` throw `not-differentiable` or `unsupported-function` with the call's span (S-03). Their derivative is 0 almost everywhere; returning 0 would hide the jumps.

**Steps** (Q1). With `steps: true`, each order adds two entries:

```ts
type DerivativeRule =
  | 'constant' | 'variable' | 'sum' | 'constant-multiple' | 'product' | 'quotient'
  | 'power' | 'exponential' | 'general-power' | 'logarithm' | 'root' | 'absolute-value'
  | 'trigonometric' | 'inverse-trigonometric' | 'hyperbolic' | 'inverse-hyperbolic';

type DerivativeStep =
  | { readonly kind: 'differentiate'; readonly order: number; readonly rule: DerivativeRule;
      readonly chain: boolean;            // the outer function's argument is not the bare variable
      readonly before: Expr; readonly after: Expr }
  | { readonly kind: 'simplify'; readonly order: number; readonly rules: readonly SimplifyRule[];
      readonly before: Expr; readonly after: Expr; readonly conditions: readonly Condition[] };
```

- No English is baked in. The rule id is the i18n key. `ruleFormula(rule)` returns a language-neutral LaTeX formula, for example `(fg)' = f'g + fg'`.
- The `chain` flag fixes the `sin(x^2)` chip, and `exponential` fixes the `2^x` chip (§1).
- A simplify step whose `after` prints the same as its `before` is omitted (DE 384 does this today).
- The header step (Leibniz notation of the input) stays Ekuation's.

## 10. API sketch

```ts
// @arki/cas — shared types, errors, limits
export type CasInput = Expr | string;
export type CasOptions = {
  readonly language?: Language;                 // default: scientific
  readonly assume?: Assumptions;
  readonly limits?: Partial<CasLimits>;
  readonly signal?: AbortSignalLike;
  readonly numbers?: 'fraction' | 'decimal';    // Q3; default 'fraction'
};
export type CasResult = { readonly result: Expr; readonly conditions: readonly Condition[] };
export class CasError extends MathError { /* code, remediation, span? (input span) */ }
export class CasLimitError extends ResourceLimitError { /* budget, limit, actual */ }
export function conditionToLatex(condition: Condition): string;

// @arki/cas/derivative
export function derivative(
  input: CasInput, variable: string,
  options?: CasOptions & { readonly order?: number; readonly steps?: boolean; readonly simplify?: boolean },
): CasResult & { readonly steps: readonly DerivativeStep[] };   // [] unless steps: true
export function ruleFormula(rule: DerivativeRule): string;

// @arki/cas/simplify
export function simplify(input: CasInput, options?: CasOptions): CasResult & { readonly applied: readonly SimplifyRule[] };

// @arki/cas/polynomial
export function expand(input: CasInput, options?: CasOptions): CasResult;
export function collect(input: CasInput, variable: string, options?: CasOptions): CasResult;
export function rationalize(input: CasInput, options?: CasOptions):
  { readonly numerator: Expr; readonly denominator: Expr; readonly conditions: readonly Condition[] };
export function polynomialIn(input: CasInput, variable: string, options?: CasOptions):
  | { readonly kind: 'polynomial'; readonly coefficients: readonly Rational[]; readonly conditions: readonly Condition[] }
  | { readonly kind: 'rational'; readonly numerator: readonly Rational[]; readonly denominator: readonly Rational[];
      readonly conditions: readonly Condition[] }
  | { readonly kind: 'other'; readonly reason: 'transcendental' | 'symbolic-coefficient'; readonly span: Span };
export function gcd(a: CasInput, b: CasInput, options?: CasOptions): CasResult;
export function factor(input: CasInput, variable: string, options?: CasOptions): {
  readonly content: Rational;
  readonly factors: readonly { readonly factor: Expr; readonly multiplicity: number }[];
  readonly complete: boolean;
};
```

Coefficient arrays are ascending, like mathjs's, so EQ's indexing (EQ 373–404, 791–960) does not change.

## 11. Errors

| Error | Thrown by | Carries |
| --- | --- | --- |
| `CasError extends MathError` | any verb | `code`, `remediation`, `span?` (into the input's `source`) |
| `CasLimitError extends ResourceLimitError` | any verb | `budget`, `limit`, `actual` |
| `ParseError`, `ExprLimitError` | string input, via expr | as in expr |
| `signal.reason` | any verb with a `signal` | whatever the host aborted with |

`CasError.code` follows `ParseError`'s pattern (a string union, not `ARKI_…`): `unsupported-function`, `not-differentiable`, `not-in-domain` (`i`, or a function cas has no real meaning for), `bad-variable` (the variable is a constant or function name; replaces DE 473–491), `not-rational` (`rationalize` on a transcendental input). Messages are English; apps translate by `code`.

## 12. Budgets and cancellation

Checked before the expensive work. Unlike expr, rewriting has no static cost bound, so a fuel counter backs the static checks.

| Budget | Default | Checked |
| --- | --- | --- |
| `nodes` | 5 000 | on input; output tree size computed from the DAG (cheap count) before printing |
| `depth` | 256 | on input; internal algorithms are iterative |
| `terms` | 10 000 | before `expand`: multinomial count C(n+k−1, k−1) for `(k terms)^n`, products of term counts |
| `degree` | 1 000 per variable; 64 for `gcd` and `factor` | before powers, expansion, gcd and factor |
| `digits` | 1 000 per coefficient | before multiply (sum of digits), before power (n × digits), PRS growth bound before gcd |
| `order` | 10 | before `derivative` starts |
| `fuel` | 100 000 rewrite and arithmetic steps per call | counted; the `signal` is checked every 1 024 units and between orders |

Expression swell is the main risk: repeated quotient and product rules, `(x + y + 1)^n`. Hash-consing keeps derivatives linear in the DAG, and normalization between orders stops growth from compounding. The output size check turns what is left into a `CasLimitError`, never a hang.

## 13. Testing and correctness evidence

- **Property tests (fast-check, dev-only).**
  - `simplify`, `expand`, `rationalize`: on generated rational-function trees (`+ - * / ^int`, small literals, 1–3 names), `evaluate(result)` equals `evaluate(input)` **exactly** in `@arki/expr/rational`, at random rational points where the input is defined and the conditions hold. Where the input is defined, the result must be defined too.
  - Kernel rules: kernels are replaced consistently by fresh variables, so algebraic rules are tested exactly. Rules that are about kernels (`exp-ln`, `parity`, …) are tested in float at random points within 1e-12 relative.
  - **Conditions are necessary.** For each condition-bearing rule, a generated point that breaks the condition must show the input undefined (or different). A condition that never matters is a bug too.
  - `derivative`: polynomial inputs match `polynomialDerivative` of the coefficients exactly. All inputs match `@arki/math/differentiate` `derivative(f, x)` at random points within its error estimate. Linearity and the product rule hold as `simplify(lhs - rhs) = 0` on rational inputs.
  - `gcd` divides both inputs; `gcd · lcm = a · b` up to a unit; `expand(product of factor's output) = input`; square-free parts have no repeated roots.
  - `print`/`parse` round trip of every result (it holds by construction; the test keeps it true).
- **Oracle fixtures.** SymPy generates derivatives, gcds and factorizations for a fixed set, offline and dev-only, committed as JSON (the Wave 1 mpmath pattern). No runtime dependency.
- **Differential test vs mathjs** on the Ekuation corpus: values at sample points within 1e-9 relative, or both fail, or the case is on the intended-difference list (§15).
- **Fuzzing** with random and grammar-aware ASTs, hostile cases included (`(x+1)^10000`, `x^(10^9)`, deep nesting, 5th derivative of `exp(x^x)`): only `CasError`, `CasLimitError`, expr's errors or math's errors may escape, and each input finishes within 100 ms.
- **Security.** No `eval`, no `new Function`; rule tables are frozen data; names live in `Map`s, so `constructor` and `__proto__` are ordinary variables (tested); tampered AST JSON arrives through expr's `fromJSON`.
- **Acceptance:** one test per S-01–S-13.

## 14. Bundle size and benchmarks

| Entry (real import, min+gz, on top of expr core and `@arki/math/rational`) | Target |
| --- | --- |
| `@arki/cas/polynomial` without `factor` | ≤ 9 KB |
| `@arki/cas/simplify` | ≤ 12 KB |
| `@arki/cas/derivative` (includes simplify) | ≤ 15 KB |
| `factor` | ≤ 3 KB more |

These are targets, not measurements. Build step 1 commits the measured numbers and `size-limit` enforces them from then on, as in expr. The README prints mathjs pruned with `create()` and only `derivativeDependencies`, `simplifyDependencies` and `rationalizeDependencies`, measured the same way.

**Benchmarks** (`bench/*.bench.ts` on `@arki/bench`, house rules):
- **Competitors.** mathjs, pruned: the incumbent, same verbs. **Algebrite**: exact rationals and `d`/`expand`/`factor`/`gcd`, the closest semantic peer. **nerdamer** (core plus Calculus and Algebra): the most-used JS CAS for derivatives. Cortex Compute Engine is a candidate only if a per-feature import can be measured; otherwise it is listed as not comparable. SymPy is an oracle, not a competitor (not JS).
- **Cases.** The four DE presets at order 1; `exp(x)*cos(x)` at order 5; `(x^2 + 1)/(x - 1)` at order 3; `simplify` of a raw quotient-rule result; `expand((x + y + 1)^10)` and `expand((x + 1)^50)`; `polynomialIn` on the EQ corpus; `gcd` of two degree-30 polynomials with a known common factor; `factor` of an expanded `(x - 1)^3 (x + 2)(2x - 3)`.
- **Contract check before timing.** Outputs must agree with ours at 5 random points (float, 1e-9 relative), and polynomial coefficients exactly. Otherwise the case is "not comparable", not a win.
- **Never gamed.** No cache across calls keyed by input; per-call hash-consing is algorithmic and is rebuilt every call. No input-shaped fast paths. README numbers come only from an idle-machine run, and losses are published.

## 15. Ekuation migration

**Slice C — EQ** (needs only `polynomialIn`).
- `math.rationalize` (EQ 784) becomes `polynomialIn(parseEquation(…) as lhs − rhs, variable)`. `kind: 'other'` means transcendental. `rational` solves the numerator and drops roots of the denominator. Coefficients stay exact until the solver boundary, where they become floats for `quadraticRoots`/`cubicRoots`.
- Linear roots become exact (`-c0/c1` over ℚ), so `trySymbolicForm` is no longer needed for them.
- Identity messages carry conditions: `x/x = 1` says "every x except 0".
- Newton's derivative (EQ 301) goes away when the scan moves to `@arki/math/roots` (R-04). If that change is not ready, `derivative` from cas fills in.

**Slice D — DE.**
- `parse`, `names` and `compile` come from expr; `derivative(…, { order, steps: true })` from cas.
- `simplifiedString = print(result)`, `derivativeLatex = toLatex(result)`. `derivativeString` is only read by tests (DE test 281, 308–311); it becomes the rule-applied form of the last order.
- Steps map to `DerivationStep`: `expression = toLatex(after)`, the rule chip from `rule` + `chain`, the explanation from Ekuation's locale files by rule id (this also fixes the English-only panel).
- Conditions are shown in the result note: "valid for x > 0".

**Gate:** `__tests__/cas-migration-corpus.test.ts`, built like `expr-migration-corpus.test.ts`.
- Corpus: every expression in DE and EQ tests, quick-start presets, input hints (DE 160–164) and locale examples (`locales/en`, `locales/de`).
- DE: derivative values at 7 points in `[xMin, xMax]`, for each order, within 1e-9 relative, or both fail. EQ: equal `equationType`, coefficients within 1e-12 relative.
- Every other outcome is listed in `INTENDED` with its reason. A listed case that no longer differs fails, so the list cannot go stale.
- **Known intended differences** (from the probe): `2^x` and `log(x, 2)` keep `ln(2)` exact; `x/x = 1` becomes "identity except x = 0"; `pi*x = 1` becomes transcendental (or per Q6); the `sin(x^2)` and `2^x` chips; `abs(x)` → `sign(x)` with `x ≠ 0` instead of `abs(x)/x` (same values); the printed forms differ everywhere (the gate compares values, never strings).
- **Freeze, then remove.** Once the gate is green, the mathjs side is written once to a JSON fixture, so the gate keeps running without mathjs. Then `mathjs` leaves `apps/ekuation/start/package.json` (line 71), and the mathjs legs of `expr-migration-corpus.test.ts` and `linear-algebra-migration.test.ts` are frozen the same way or deleted, as their headers already plan.

## 16. Package layout and cross-runtime constraints

```
packages/cas/
  src/index.ts         types, CasError, CasLimitError, limits, conditionToLatex
  src/dag.ts           internal: hash-consed terms, kernels, canonical order
  src/poly.ts          internal: sparse Poly over Rational; dense univariate ops
  src/ratfun.ts        internal: RatFun normal form, cancellation, conditions
  src/sign.ts          internal: the sign oracle
  src/emit.ts          internal: canonical tree → print → parse
  src/simplify.ts      → @arki/cas/simplify
  src/derivative.ts    → @arki/cas/derivative
  src/polynomial.ts    → @arki/cas/polynomial
  bench/  test/  .size-limit.json
```

- Dependencies: `@arki/expr` and `@arki/math` (`rational`, `integer`, `errors`). Neither depends on cas.
- Dev-only: fast-check, mathjs, algebrite, nerdamer, size-limit.
- Pure ESM; the `@arki/eslint-config/library` preset applies (no `node:*`, `process`, `Buffer`, `toSorted`).
- Hermes: no `eval` or `new Function`; BigInt (already required by `Rational`); recursion bounded by the depth budget, with the internal algorithms iterative. `test:runtimes` runs the built package on Node, Bun, Deno, a browser and Hermes, including a 256-deep input and a 5th-order derivative.

## 17. Deliberately left out

- Integration, limits, series, `solve` (EQ solves numerically and by closed forms in `@arki/math`).
- Exact radical roots of cubics and quartics, and root isolation (R-06 stays in Ekuation).
- Trig identities beyond parity and special values; log expansion and contraction; radical denesting.
- The complex domain, piecewise results, inequalities, assumptions beyond the four signs.
- Implicit differentiation as a verb. It is reachable as `-∂F/∂x / ∂F/∂y` with two `derivative` calls (`derivative-calculator/docs/claude.research.md` 196–210 plans it); no corpus code needs it yet.
- Full multivariate factoring, Gröbner bases, user rewrite rules, a mathjs compatibility layer.

## 19. Open questions for the founder

1. **Steps in v1?**
   - A. No steps. Ekuation re-implements `detectRule` on the expr AST. Smallest cas; the chip bugs stay Ekuation's to fix.
   - B. Per-order trace: top-level rule + `chain` flag + rule-applied form + simplified form. Matches today's UI and fixes the chips; small (estimate: about 1 KB).
   - C. Full rule-by-rule derivation tree. Textbook quality; much larger, and a presentation design of its own.
   - **Recommend B.** The types allow C later as an addition.
2. **Canonical output form?**
   - A. Fully expanded normal form. Simplest and predictable, but `exp(x)*cos(x) - exp(x)*sin(x)` and long numerators.
   - B. Expanded polynomial part, one fraction over a factored denominator, common non-polynomial factors pulled out. Reads like a textbook; slightly more code.
   - C. Match mathjs strings. Free parity; keeps the unreadable quotient forms.
   - **Recommend B.**
3. **Exact numbers in output?**
   - A. Always fractions (`x/50 + 5`). Exact and uniform; reads oddly for money-style inputs.
   - B. Decimals whenever the value terminates (`0.02*x + 5`). Friendly, but `1/3` and `0.5` then mix in one result.
   - C. An option, default fractions; Ekuation picks decimals when the input used decimals.
   - **Recommend C.**
4. **How are assumptions supplied?**
   - A. Per call, per variable sign assumptions; real-only; conditions always returned. Precise; one more option to learn.
   - B. One global flag (real or complex); conditions returned. Simpler; can never prove `x > 0`, so `(x^a)^b` rules never fire.
   - C. None: never apply domain-sensitive rules. Safest; leaves `sqrt(x)^2` and `exp(ln(x))` untouched.
   - **Recommend A.**
5. **Where mathjs is wrong or lossy, match it or correct it?**
   - A. Correct (exact `ln(2)`, "identity except x = 0", `sign(x)` with `x ≠ 0`, chip fixes), each on the gate's intended list with a release note. Users see small changes.
   - B. Match mathjs now, fix later. Zero visible change; ships known-wrong answers under a new engine.
   - **Recommend A.**
6. **Symbolic constants in coefficients (`pi*x = 1`)?**
   - A. Coefficients over ℚ only; `pi` makes it `other`, and EQ solves numerically. Simple and exact; loses the closed form.
   - B. Coefficients over ℚ(π, e) as `Expr`; EQ evaluates them in float for its closed-form solvers. Keeps `x = 1/π`; more API surface.
   - C. Treat constants as floats. Breaks the no-silent-coercion rule.
   - **Recommend A for v1**; B is an additive change later.
7. **How complete is `factor` in v1?**
   - A. Content + square-free + rational linear factors, with a `complete` flag. Exact, small, honest; misses `x^4 + 4 = (x^2 - 2x + 2)(x^2 + 2x + 2)`.
   - B. Full univariate factoring over ℚ (Berlekamp or Cantor–Zassenhaus + Hensel lifting + recombination). Complete; several KB and the hardest code in the package.
   - C. Leave `factor` out of v1; no corpus code needs it.
   - **Recommend A.** It is enough for exact rational roots later, and B can follow on demand.
