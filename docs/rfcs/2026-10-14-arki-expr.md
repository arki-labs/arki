# RFC: `@arki/expr`, a safe expression language on `@arki/math`

- **Status**: draft for founder review (2026-10-14). Ships in Wave 3 after review.
- **Sources**: `.work/math-best-in-industry/synthesis.md` Wave 3 item 6 (Fable and Astra, blind, merged); `review-fable.md` § "Parser / CAS"; `review-astra.md` § "Language". Requirements come from a survey of the 15 Ekuation files that import `mathjs` (§3).
- **Builds on**: `@arki/math` 0.0.9 (`Decimal`, `Rational`, `Complex`, `RoundingMode`, `MathError` and its subclasses); `docs/rfcs/2026-10-14-arki-structure.md` § 4 (layers: `expr` sits in `foundation`, above `math`).
- **Sibling**: `@arki/cas` (Wave 3 item 7) is a separate RFC. It depends on this AST; this package never depends on it.

## 1. Problem

Ekuation is the only reason mathjs is in the repo. It needs a parser and evaluator for user-typed formulas: a scientific keypad, a graphing calculator, plotters, and numeric solvers. Today that costs:

- **Size.** mathjs is a 636 KB browser bundle; Ekuation imports it as `import * as math`, so nothing is pruned.
- **Fragile glue.** Call sites rewrite input with string replacements before mathjs sees it: `ln(` → `log(…, e)`, `|…|` → `abs(…)`, and `sin(` → `sin(pi/180*` in degree mode. In K2 that turns `sin(30+60)` into `sin(pi/180*30+60)`; in K1 and K2 it turns `asin(0.5)` into `asin(pi/180*…)`. Inverse-trig results are never converted back to degrees.
- **Untyped results.** `evaluate` returns `number`, `Complex`, `BigNumber`, `boolean` or a matrix. Every call site has its own `typeof … 'toNumber' in result` ladder.
- **Errors by string matching.** The keypad maps errors by `message.includes('Undefined function')`.
- **No exact path.** `0.1 + 0.2` in a calculator shows `0.30000000000000004` unless every site rounds by hand.
- **Security surface.** mathjs is a general language (member access, `import`, units, matrices, strings). Its own docs list `import`, `createUnit` and `reviver` as high-risk. We need none of that.

## 2. Goals and non-goals

**Goals**
1. One grammar, specified exactly (§4), with a typed, versioned AST that carries source spans (§6).
2. Explicit numeric domains: float, `Decimal`, `Rational`, float64 `Complex` (§8). Exact domains are exact or throw. No silent float coercion.
3. Safe by construction: the language can only call what the host registered (§9). No codegen; closures only.
4. Parse once, compile once, evaluate many times. A graph of 10 000 points costs one parse and one compile (§10).
5. Every input is bounded: tokens, depth, nodes, steps, digits, plus cancellation (§11).
6. Canonical text and LaTeX printing (§12). Locale input and display, locale-free storage (§5).
7. Under 15 KB min+gz for parser plus the float domain (§13). Faster than pruned mathjs on parse, compile and evaluate (§14).
8. Runs on Node, Bun, Deno, browsers and Hermes (§18).

**Non-goals**
- **No CAS.** `derivative`, `simplify`, `rationalize`, `expand` belong to `@arki/cas`.
- **No member access, indexing, imports, assignment, user-defined functions, strings, objects, booleans, comparisons, matrices or ranges** in the language.
- **No units** (`5 km`). Revisit after Wave 4's dimensional analysis lands in `@arki/math/units`.
- **No mathjs compatibility mode.** We match mathjs where Ekuation's corpus needs it (§3), and document every deliberate difference.
- **No parser inside `@arki/math`** (synthesis "Never" list).

## 4. Grammar

### 4.1 EBNF

```ebnf
expression = sum ;
equation   = sum "=" sum ;                      (* parseEquation only; at most one "=" *)
sum        = product { ( "+" | "-" ) product } ;
product    = unary { ( "*" | "/" ) unary | implicit } ;
implicit   = power-no-sign ;                    (* juxtaposition; rules in 4.3 *)
unary      = ( "-" | "+" ) unary | power ;
power      = postfix [ "^" unary ] ;            (* right-assoc: exponent is a unary *)
postfix    = primary { "!" } ;
primary    = number | name | call | "(" sum ")" | "|" sum "|" | "√" primary ;
call       = name "(" [ sum { sep sum } ] ")" ;  (* only when name is a registered function *)
number     = ( digits [ dot digits ] | dot digits ) [ ( "e" | "E" ) [ "+" | "-" ] digits ] ;
name       = letter { letter | digit | "_" } ;  (* letter = A–Z, a–z, _, Greek α–ω, Α–Ω *)
```

`dot` and `sep` come from the syntax (§5): `.` and `,` by default. Whitespace is ignored except as a separator between tokens. Aliases: `×` and `·` read as `*`, `÷` as `/`, `−` as `-`, `π` as `pi`, `√` as a call to `sqrt`.

### 4.2 Precedence (high to low)

| Level | Operators | Associativity | Examples |
| --- | --- | --- | --- |
| 1 | literals, names, calls, `( )`, `\| \|`, `√` | — | `sin(x)`, `\|x-1\|` |
| 2 | postfix `!` | left | `3!^2 = 36` |
| 3 | `^` | right | `2^3^2 = 512`, `2^-1 = 0.5`, `2^3! = 64` |
| 4 | unary `-` `+` | right | `-2^2 = -4`, `-x! = -(x!)` |
| 5 | `*` `/` and implicit multiplication | left | `1/2x = x/2`, `2x^2 = 2·x²` |
| 6 | binary `+` `-` | left | `2-3 = -1` (never `2·(-3)`) |
| 7 | `=` | none | equations only |

Implicit multiplication shares level 5 with `*` and `/` and reads left to right: `1/2x` is `(1/2)·x`, as Wolfram Alpha reads it. mathjs has its own special cases here; we do not copy them. The differential test (§19) lists every corpus expression where the two disagree, and each one gets a release note.

### 4.3 Implicit multiplication and its ambiguities

Juxtaposition means multiplication when the left side ends an operand and the right side starts one without a sign:

| Left \ right | name | `(` | number | `\|` |
| --- | --- | --- | --- | --- |
| number | `2x`, `2pi` ✓ | `2(x+1)` ✓ | error | `2\|x\|` ✓ |
| `)` or `\|` (closing) | `(x+1)x` ✓ | `(x+1)(x-1)` ✓ | error | ✓ |
| name (variable or constant) | `x y` ✓ | `x(y+1)` ✓ (see below) | error | ✓ |

- **`f(x)` vs `x(y)`.** A name followed by `(` is a call only if the name is a registered function. A variable or constant followed by `(` is a product. That needs the function names at parse time, so `parse` takes a `language` (§9). An unknown name followed by `(` is a `ParseError` (`not-a-function`), never a guess.
- **Multi-letter names (founder decision: split letters).** An identifier resolves in this order: (1) a declared variable, registered constant or registered function with exactly that name wins (`rate`, `pi`, `sin`, `xy` if the host declared `xy`); (2) otherwise, if every single letter is a declared variable or constant, the identifier is their implicit product (`xy` → `x*y`, `2xy` → `2*x*y`, `xpi` is not split because `pi` is not a single letter — it is `unknown-name`); (3) otherwise compile fails with `unknown-name`, listing the letters that are not declared. Function names never split (`sin` is never `s*i*n`), and a split never reaches into a function call (`xsin(y)` is `unknown-name`, not `x*sin(y)` — the user writes `x sin(y)` or `x*sin(y)`). The split happens in `compile`, because only `compile` knows the declared variables. The AST keeps the identifier as typed, so `print` round-trips it. The compiled function lists each split it made (`f.readings`: `{ span, name: 'xy', letters: ['x', 'y'] }`), so a UI can show `x·y` and explain the reading.
- **A number after an operand** (`x2`, `(a)2`) is an error: `x2` is a name, and `(a)2` is almost always a typo.
- **`2e+1`** lexes as the literal 20, as in JavaScript. `2e` alone is `2·e`. The canonical printer writes `2 * e + 1` for the other reading, so stored text is never ambiguous.
- **Functions need parentheses.** `sin x` and `sin^2(x)` are errors with a hint (`write sin(x)^2`).
- **Absolute-value bars.** A `|` opens when it stands where an operand is expected (start, after an operator, `(`, separator or an opening `|`), and closes otherwise. `||x|-|y||` nests correctly; `|x|y|` is an `unbalanced-bar` error at the third bar.
- **`2^3x`** is `(2^3)·x = 8x`: the exponent is a unary, and implicit multiplication happens at level 5. Parse returns a `warning` for this and for `a/bc`, so a UI can show the reading.

## 5. Locale

Input syntax is explicit, never sniffed:

```ts
type Syntax = { readonly decimal: '.' | ','; readonly separator: ',' | ';' };
const canonical = { decimal: '.', separator: ',' } as const; // the default
const decimalComma = { decimal: ',', separator: ';' } as const; // de, fr, ro, …
```

- With a decimal comma, the argument separator must be `;` (the spreadsheet convention). `{ decimal: ',', separator: ',' }` is rejected when the syntax is built.
- Group separators are never accepted inside expressions: `1,234` would collide with the separator.
- `syntaxFor(locale)` maps a locale to one of the two presets through `Intl` **when called**, never at module load. On Hermes without `formatToParts` it throws `UnsupportedFeatureError`, as `@arki/math/parse` does; hosts can pass a preset instead.
- **Storage is locale-free.** Apps store `print(expr)` (canonical syntax). A German user types `sin(0,5; 2)`, the URL and database hold `sin(0.5, 2)`, and the display prints it back in German. Literal text survives the trip: `0,50` is stored as `0.50`.

## 6. The AST

Plain, JSON-serializable objects. Discriminated on `kind`. Every node has a span.

```ts
type Span = { readonly start: number; readonly end: number }; // UTF-16 offsets into source

type Node =
  | { kind: 'number'; raw: string; span: Span } // canonical literal text, e.g. '0.50', '1e-7'
  | { kind: 'name'; name: string; span: Span } // variable or constant
  | { kind: 'unary'; op: '-' | '+'; arg: Node; span: Span }
  | { kind: 'binary'; op: '+' | '-' | '*' | '/' | '^'; left: Node; right: Node; implicit: boolean; span: Span }
  | { kind: 'call'; fn: string; args: readonly Node[]; notation: 'call' | 'bars' | 'radical'; span: Span }
  | { kind: 'factorial'; arg: Node; span: Span }
  | { kind: 'group'; inner: Node; span: Span }; // parentheses the user wrote

type Expr = { readonly version: 1; readonly source: string; readonly root: Node; readonly warnings: readonly Warning[] };
type Equation = { readonly version: 1; readonly source: string; readonly left: Node; readonly right: Node; readonly warnings: readonly Warning[] };
```

- **Literal text is kept** (`raw`). Each domain reads it with its own constructor, so `0.1` is exactly `1/10` in Rational and Decimal and `Number('0.1')` in float.
- **Groups are kept**, so printing is faithful and `@arki/cas` can see what the user wrote. `notation` keeps `|x|` and `√x` printing as typed.
- **Helpers:** `walk(node, visit)`, `children(node)`, `names(expr)` → `{ variables, constants, functions }`. `names` replaces Ekuation's hand-kept `MATH_FUNCTIONS` filter (C-23).
- **Versioning.** `version` bumps on any breaking AST change. Pre-1.0 there is no compatibility shim: `fromJSON` accepts only the current version, validates every node and runs the budgets. Stored user data is canonical text, not AST JSON, so a version bump never strands it. AST JSON is for caches and worker hand-off.

## 7. Errors

| Error | Thrown by | Carries |
| --- | --- | --- |
| `ParseError extends MathError` | `parse`, `parseEquation`, `compile`, `fromJSON` | `code`, `span`, `position`, `expected: readonly string[]`, `found: string` |
| `ExprLimitError extends ResourceLimitError` | any stage | `budget` (`'length' \| 'tokens' \| 'depth' \| 'nodes' \| 'steps' \| 'digits'`), `limit`, `actual` |
| math's errors, unchanged | evaluation | as in `@arki/math/errors` |
| `signal.reason` | evaluation with a `signal` | whatever the host aborted with |

`ParseError.code` is one of `unexpected-token`, `unexpected-end`, `unbalanced-paren`, `unbalanced-bar`, `bad-number`, `not-a-function`, `unknown-name`, `arity`, `name-conflict`, `not-in-domain`. Messages are English; apps translate by `code` (Ekuation ships `de.json`). The rule: **anything about the text is a `ParseError` with a span; anything about the values is a math error.** So `sin(x)` in the Rational domain fails at compile (`not-in-domain`, pointing at `sin`), while `1/x` at `x = 0` fails at evaluation with `DivisionByZeroError`.

Evaluation reuses math's classes: `DivisionByZeroError`, `RoundingNecessaryError`, `InvalidArgumentError` (outside a function's domain: `sqrt(-1)` in float, `ln(0)`), `NumericRangeError` (overflow), `ConvergenceError`. `instanceof` checks written against `@arki/math` keep working. These errors carry no span in v1 (open question 6).

## 8. Evaluation domains

Each domain is its own subpath with its own `compile`. Function availability is a static table per domain, checked at compile time.

| Domain | Values | `+ - *` | `/` | `^` | Transcendental | Constants |
| --- | --- | --- | --- | --- | --- | --- |
| `float` | `number` | IEEE | IEEE; `/0` throws | `Math.pow` | all of C-08 | `pi`, `e` as doubles |
| `decimal` | `Decimal` | exact | exact if it terminates, else round to `{ scale, rounding }` | integer exponent exact; otherwise `decimal-math` `pow` at `scale` | `sqrt cbrt nthRoot exp ln log log10 log2` correctly rounded at `scale`; trig `not-in-domain` | `pi`, `e` rounded at `scale` |
| `rational` | `Rational` | exact | exact | integer exponent exact; rational exponent only when the root is exact (`8^(2/3) = 4`) | `sqrt`/`nthRoot` only when exact; others `not-in-domain` | `pi`, `e` `not-in-domain` |
| `complex` | `Complex` (float64) | float | float; `/0` throws | principal branch | `sqrt exp ln pow` (from `@arki/math/complex`) | `pi`, `e`, `i` |

**Exactness rules**
- **Float** is honest float: fast, for plotting and numeric solvers. A single evaluation throws typed errors instead of returning `NaN` or `Infinity` (`sqrt(-1)` → `InvalidArgumentError`, `1/0` → `DivisionByZeroError`, overflow → `NumericRangeError`). The bulk `sample` call (§10) is the one place `NaN` appears: it marks a gap in a `Float64Array` of plot points, because 5 000 thrown exceptions per frame is the wrong cost for "this point has no value". (Open question 4.)
- **Decimal** is exact or rounds where you said. `+ - *` never round. An inexact step rounds to the context `{ scale, rounding }`. The default rounding is `unnecessary`, so an inexact step throws `RoundingNecessaryError` unless the caller chose a mode — the same default as `Decimal.dividedBy`. `evaluate('0.1+0.2', decimal)` is `0.3`.
- **Rational** never rounds. A result that is not rational (`2^(1/2)`) throws `RoundingNecessaryError`: the exact answer exists but this type cannot hold it. There are no special cases such as `sin(0) = 0`.
- **Complex** is float64 and never claims exactness. Exact complex arithmetic would need rational components; it is out of scope.
- **Reporting.** `f.detailed(scope)` returns `{ value, exact }`. `exact` is false once any step rounded. Calculators use it to show `≈`.
- **No silent coercion.** A function missing in a domain is a compile error, never a fallback to float. A host that wants float trig on decimals converts explicitly and says so.

**Integer-only operations.** `factorial` uses `@arki/math/integer` on integers in every domain; for non-integers it uses `gamma(x + 1)` in float only. `mod`, `floor`, `ceil`, `round`, `fix`, `sign`, `abs` are exact in Decimal and Rational.

**Angles.** `angle: 'rad' | 'deg'` is a compile option, not syntax. It converts the argument of forward trig functions and the result of inverse trig functions, at any nesting depth (C-12). The AST stays angle-free.

## 9. Languages: host-registered functions and constants

The language is a whitelist. Nothing is callable unless it is in the language passed to `parse`.

```ts
import { defineLanguage, scientific } from '@arki/expr';

const physics = defineLanguage({
  extends: scientific,
  functions: { hypot: { arity: [2, 16], latex: '\\operatorname{hypot}' } },
  constants: { g: { latex: 'g' } },
});
```

- A language holds only names, arities and LaTeX templates. It is domain-free and small, so `parse` never pulls in numeric code.
- Implementations are supplied per domain at compile. Built-in names (`scientific`) come with each domain subpath. Host names must be implemented by the caller, and the types enforce it:

```ts
import { compile } from '@arki/expr/float';

const f = compile(parse('hypot(x, g)', { language: physics }), {
  variables: ['x'],
  functions: { hypot: Math.hypot }, // required: the language declares it
  constants: { g: 9.80665 }, // required
});
```

- `defineLanguage` validates names against the `name` grammar and rejects collisions between functions, constants and built-ins. Tables are copied into `Map`s and frozen: a name like `constructor` or `__proto__` is just an unknown name.
- Host functions receive domain values only (`number`, `Decimal`, …). They never see the AST, the scope or other functions. Each call counts as one step; a host may declare a higher `cost`.

## 10. Compile once, evaluate many

```ts
import { parse } from '@arki/expr';
import { compile, evaluate } from '@arki/expr/float';

evaluate('2^10 - 1'); // 1023 — parse + compile + call, for the keypad (C-15)

const expr = parse('2x^2 + sin(x)'); // default language: scientific
const f = compile(expr, { variables: ['x'], angle: 'rad' });
f({ x: 1.5 }); // number; throws typed errors
f.at(1.5); // single-variable fast path, no scope object
f.sample(xs, out); // Float64Array in, Float64Array out; NaN = gap (C-22)
```

```ts
import { compile as compileDecimal } from '@arki/expr/decimal';

const price = compileDecimal(parse('base * (1 + rate)'), { variables: ['base', 'rate'], scale: 2, rounding: 'halfEven' });
price({ base: '19.99', rate: '0.19' }).toString(); // '23.7881' — multiplication never rounds
compileDecimal(parse('total / 3'), { variables: ['total'], scale: 2, rounding: 'halfEven' })({ total: '10' }).toString(); // '3.33'
```

- **Variables are declared.** `compile` resolves each name to a slot. An undeclared name fails at compile with `unknown-name` and a span, before any point is evaluated. A declared variable that shadows a constant is `name-conflict` (PO stops passing `pi` and `e`, C-18).
- **Scope.** Values for declared variables are required; a missing one is `InvalidArgumentError`. Extra keys are ignored. Exact domains accept the same inputs as `decimal()` / `ratio()`.
- **Closures.** `compile` turns each node into a closure specialised by operator and arity (`(s) => l(s) + r(s)`). Constant subtrees fold at compile time in exact domains, and in float only when folding cannot change a result (no folding across `NaN`-producing operations).
- **Two closure trees in float.** The checked tree serves `f()` and `f.at()`. The unchecked IEEE tree serves `sample()` and is built lazily on its first call.
- **Equations.** `compileEquation(eq, opts)` returns `{ left, right, difference }`, all sharing slots, for EQ's back-substitution (C-14, C-17).

## 11. Budgets and cancellation

Checked before the expensive work, never after.

| Budget | Default | Checked |
| --- | --- | --- |
| `length` | 10 000 chars | before lexing |
| `tokens` | 5 000 | while lexing |
| `depth` | 256 | while parsing (also the closure-nesting bound) |
| `nodes` | 5 000 | while parsing and in `fromJSON` |
| `steps` | 10 000 000 per call | statically: nodes × points for `sample`; host `cost` added |
| `digits` | 1 000 | exact domains: literal digits at compile; result size estimated before `pow` and `factorial` |

- The language has no loops, recursion or user functions, so one evaluation costs at most `nodes` steps. That lets the step budget be checked once, at compile or at the start of `sample`, with no counter in the hot loop.
- Digit growth is the real risk in exact domains: `9^9^9` in Rational. The estimate (`exponent × digits(base)`, log-gamma for factorial) throws `ExprLimitError` before the `bigint` work starts. `@arki/math`'s own 10 000-digit cap remains as a backstop.
- **Cancellation.** `sample` and exact-domain calls take `{ signal }`. `sample` checks it every 1 024 points; exact domains check it before each operation above 100 digits. A single float evaluation is microseconds and does not check.
- **Isolation.** Untrusted workloads run in a Worker. Expressions cross as canonical text or AST JSON; both are validated on arrival.

## 12. Printing

- `print(expr, { syntax?, style? })`. The `canonical` style (default) is ASCII, `.` decimals, `,` separators, explicit `*`, single spaces around binary `+ -`, groups as written, literals as `raw`: `2 * x^2 + sin(x)`. The `display` style uses the given syntax, implicit multiplication where it reads the same, `−` and `·`.
- **Round trip.** `parse(print(e))` equals `e` apart from spans. This is a property test, not a hope (§19).
- `toLatex(expr)` from `@arki/expr/latex`: `\frac{}{}` for `/`, `^{}`, `\sqrt{}` and `\sqrt[n]{}`, `\left| \right|`, `\sin`, `\pi`, `n!`, `\cdot` for explicit `*` and plain juxtaposition for implicit. Host functions use their `latex` template, otherwise `\operatorname{name}`.

| `@arki/expr/decimal`, `/rational`, `/complex` | expr glue ≤ 4 KB each on top of the math subpaths they import |

Measured with `size-limit` (esbuild, min + gzip) per subpath, one entry per row, each importing exactly what a caller would. It runs in the package's `test` task and fails on a breach. `size-limit` is new to the repo; it is a devDependency of this package only. The README prints the same measurement for mathjs pruned to the same features (`create()` with only the needed `*Dependencies`), so the comparison is like for like.

## 14. Benchmarks

`bench/*.bench.ts` on `@arki/bench`, following the house rules for `@arki/*` libraries.

| Case | Input |
| --- | --- |
| parse | 15-char keypad input; 80-char graph formula; generated 2 KB expression |
| compile | the 80-char formula |
| evaluate | `sin(x)*x^2 + 3x - 1` at 10 000 points: `f.at(x)` loop and `f.sample` |
| one-shot | `evaluate('2^10 - 1')` (keypad) |
| decimal | `0.1 + 0.2`; a 6-operation price formula at scale 2 |

- **Competitors:** mathjs pruned with `create()` and `{ number: 'number' }`, plus the most-downloaded small evaluator at bench time (candidate: `expr-eval`).
- **Contract check before timing:** every competitor must return the same value (float within 4 ulps) on every case, or the case is reported as not comparable.
- **Never gamed:** no parse cache keyed by input text, no input-shaped fast paths, no weakened checks. README numbers come only from an idle-machine run; losses are published too.

## 15. Security model

| Threat | Defence |
| --- | --- |
| Prototype or member access escape (the mathjs bug class) | The grammar has no `.`, `[]`, strings or objects. Names resolve through frozen `Map`s. |
| Code injection through codegen | No `eval`, no `new Function`. Closures only. Works under a CSP without `unsafe-eval`, and on Hermes. |
| Expression-driven capability growth | No `import`, assignment or function definition. The host's language is fixed at `defineLanguage`. |
| Stack exhaustion by nesting (`((((…`) | Depth budget during parsing; a 100 000-paren input throws `ExprLimitError`, never `RangeError`. |
| CPU exhaustion | Static step bound; `sample` size checked up front; `signal`. |
| Memory exhaustion in exact domains | Digit budget on literals and estimated before `pow`/`factorial`. |
| ReDoS | A hand-written single-pass lexer; no regex in the parse path. |
| Tampered stored AST | `fromJSON` validates kind, fields, version and budgets. Canonical text is re-parsed, never trusted. |
| Host function misuse | Functions receive domain values only, never the AST or scope. |

Why closures and not generated JavaScript: codegen is the fastest path in V8, but it needs `new Function` (blocked by strict CSP and absent on Hermes) and turns every escaping bug into code execution. Closures over a small fixed operator set are fast enough; §14 proves it or reports that they are not.

## 16. Ekuation migration

**Slice A — vertical slice, the acceptance gate.** K1, K2, G.
- Delete the regex preprocessing (`ln`, `log2`, `log10`, `logy`, `nthRoot`, degree rewriting, `× ÷ −`). The grammar and `angle` cover them.
- Map errors by `ParseError.code` and error class, not message text (C-20).
- G uses `compile(…).sample` for curves, `parse` for validation, `toLatex` for display.
- **Gate:** a corpus diff test. Every expression in these calculators' tests, examples and i18n strings is evaluated by mathjs and by expr; results match within 1e-12 relative, or the difference is listed as intended (§4.2) with a release note.

**Slice B — the rest that expr alone can serve.** PA, PO, AB, IN, LI, LG, DG, EG.
- AB's `|…|` regex goes (C-11); `math.range` becomes `@arki/math/number` `range`.
- PO drops `pi`/`e` from scope.
- In parallel and independent of expr: LS and MX move to `@arki/math/linear-algebra` (R-05, including the eigenvalue work in `be415d780e`); EQ's `polynomialRoot` moves to `@arki/math/polynomial` (R-04).

**What stays on mathjs until `@arki/cas`.** DE and EQ keep mathjs for `derivative`, `simplify` and `rationalize` (R-01–R-03). Each file moves whole, so no file holds two ASTs. After slices A and B, mathjs is imported by 2 files instead of 15. It leaves `package.json` when `@arki/cas` ships.

## 18. Cross-runtime constraints

- Pure ESM, zero runtime dependencies beyond `@arki/math`; the `@arki/eslint-config/library` preset applies (no `node:*`, no `process`/`Buffer`, no `toSorted`/`toReversed`).
- **Hermes:** no `new Function` or `eval`; no `Intl` at module load (presets are plain objects; `syntaxFor` calls `Intl` lazily); recursion bounded by the depth budget, which is tested against Hermes's smaller stack.
- `test:runtimes` (`arki-runtimes`) runs the built package on Node, Bun, Deno, a browser and Hermes, including a 256-deep expression on each.

## 19. Testing

- **Grammar table tests.** Every row of §4.2 and §4.3 is a test that checks the canonical print of the parsed tree.
- **Property tests (fast-check, dev-only):**
  - `parse(print(ast))` equals `ast` (spans ignored), for generated ASTs within budgets; the same through the decimal-comma syntax.
  - `print(parse(s))` is idempotent.
  - Domain equivalence on generated `+ - * / ^int` trees with small literals: Rational and Decimal agree exactly whenever `detailed().exact` is true; float is within an error bound of the Rational result; Complex's real part matches float when the imaginary part is zero.
  - Errors agree across domains: if Rational throws `DivisionByZeroError`, so do the others.
- **Differential test vs mathjs** on the Ekuation corpus plus generated expressions in the shared subset: same value within 4 ulps, or both fail, or the case is on the intended-difference list.
- **Fuzzing the parser** with random strings and grammar-aware mutations, all budgets on: only `ParseError` or `ExprLimitError` may escape, and each input finishes within 50 ms. Minimised failures become fixtures.
- **Security tests:** `constructor`, `__proto__`, `toString` as names; deep nesting; `9^9^9` and `10000!` in Rational; a tampered AST JSON.
- **Acceptance:** one test per corpus row C-01–C-27.

## 20. Deliberately left out

- A mathjs compatibility layer or mathjs-style "takes anything" dispatch.
- Units, matrices, comparisons, booleans, strings, assignment, user-defined functions.
- Interval arithmetic (a later domain, after `@arki/math/interval`).
- Superscript digits (`x²`) as input, and splitting `sin x` without parentheses.
- Decimal trigonometry (waits for Wave 4 item 11 in `@arki/math`).

## 21. Build order

1. **Core:** lexer, Pratt parser, AST, `print`, `ParseError`, budgets, `fromJSON`. Grammar, round-trip and fuzz tests.
2. **Float domain** with `sample`, `toLatex`, size-limit and the benchmark harness. Then Slice A in Ekuation behind the corpus diff gate.
3. **Decimal and Rational** domains with the equivalence properties. Then Slice B.
4. **Complex** domain.
5. `@arki/cas` (separate RFC) consumes the AST; DE and EQ move; mathjs leaves Ekuation.

## 22. Decisions (founder, 2026-10-14)

1. **`log(x)` is the natural log.** `ln`, `log10`, `log2` and `log(x, base)` are also available. Same as mathjs and the stored Ekuation expressions.
2. **`1/2x` is `x/2`.** Implicit multiplication has the same precedence as `*` and `/`, read left to right, and the parser warns that the input is ambiguous (the warning carries a span and a "write (1/2)x or 1/(2x)" hint).
3. **Split letters** (Desmos style), with the resolution order in §3 "Multi-letter names": exact declared names first, then a split only when every letter is declared, function names never split.
4. **`sample()` is the single NaN exception.** NaN marks a gap in the `Float64Array` of plot points; every other API throws typed errors.
5. **Decimal-comma locales use `;` as the argument separator** (and only `;`), so `f(1,5; 2)` is unambiguous; stored expressions stay in the canonical dot form.
6. **No spans on evaluation errors in v1** (option C). Revisit once a calculator needs them.
7. **Complex `sin`/`cos`/`tan`/hyperbolics are added to `@arki/math/complex` before the complex domain ships**, so the domain has no surprising holes.
